日期：2026-11-02  
状态：开工前合同  
总则：[审核总则](2026-11-02-pixcake-review-index.md)  
边界编号来自 [边界条件清单](2026-11-02-pixcake-boundary-checklist.md)。

PhotoCraft 已有能力的测试还要覆盖 C++ CPU 参考实现、OpenGL readback 与 PhotoCraft 向量或 corpus 的 parity；旧 PixCake CPU/GPU 对齐只能证明旧路径一致，不能单独证明 PhotoCraft 目标已经移植。具体来源和状态见[PhotoCraft 能力来源与移植规范](../2026-11-09-photocraft-reference-and-porting-policy.md)及[像素处理状态矩阵](../../evidence/2026-11-09-pixel-processing-status-matrix.md)。

## 1. 五种测试都要有

| 编号 | 种类 | 通过标准 | 严重程度 |
| --- | --- | --- | --- |
| T-01 | 单元测试 | 已开工模块的结果码、状态迁移、替换和叠加、修订号、显示值存储、上限拒绝，能在不打开窗口的情况下断言 | 否决 |
| T-02 | 边界用例 | 审查范围内的每一条 B 编号至少一条用例。能放进内核测试的，禁止只写成手工说明 | 否决 |
| T-03 | 异常用例 | 磁盘满、权限不足、文件截断、校验失败、超时、取消、重复提交、第三方坏返回，使用假的文件系统、时钟或远端，断言结果码和「上一份好数据还在」 | 否决 |
| T-04 | 集成测试 | 下面第 3 节里，凡是相关模块已经开工的项，都有自动化运行结果 | 否决 |
| T-05 | 回归 | 单元、集成和依赖禁令重新跑过。需求第 24 节的验收扣除架构第 17 节的排除项后，已实现的条目保持通过 | 否决 |

只有测试源文件、没有这次审查的运行结果，视为没跑，T-04 和 T-05 不通过。审核记录写明命令和结果。失败被跳过、被注释或被改成永远成功，否决。

## 4. 边界和异常至少覆盖的组

下面每一组里的编号都要有用例。一个参数化测试可以覆盖同一组的多个编号。

| 组 | 编号 | 断言里要看见的结果 |
| --- | --- | --- |
| 空输入 | B-01 到 B-15 | 非成功结果码，或明确的空状态；原有数据的校验和或修订不变 |
| 上限 | B-20 到 B-26、B-21 与 C-44、C-51、C-52 | 刚好在上限上成功，越过上限失败且旧数据还在 |
| 范围外数值 | B-27 到 B-33、B-36、B-37 | 文档里没有范围外的值，全图蒙版和画笔属性没有被绕过 |
| 非法尺寸和除零 | B-40 到 B-48 | 进程不因信号退出，没有半成品，没有一笔按 0 人计算的扣点 |
| 超时和外部失败 | B-50 到 B-55、B-80 到 B-86 | 网络失败和点数不足不是同一个码；坏配置不会变成 0 点放行 |
| 并发重放 | B-60 到 B-74 | 修订号、扣点事件和图层结果编号各只有一份 |
| 磁盘和恢复 | B-90 到 B-116 | 正式文件、目标目录和账本事件与边界清单描述的一致 |

第三方返回用替身。替身要能分别给出空包、尺寸不符、超时、成功但本地已取消。只测「返回正常图片」不算 T-03 通过。

## 5. 回归时不许掉下去的产品行为

需求第 24 节是回归源表。审查已实现的用户路径时，逐条记录通过或未实现。下面这些一旦曾经通过，再坏就是回归失败：

- 四种预设是替换还是叠加，覆盖色彩前有警告事实
- 虚拟副本、无水印第二份不另扣张数；没成品不扣
- 原图不进应用包；移走后标缺失，参数还在
- `Cmd/Ctrl + S` 打开导出列表
- 不可自定义的快捷键不在自定义表里
- 重启后历史折叠成「上一次保存」
- 带 Free 标记的分组与其他能力同样要求：已注册的有参数模式、界面和绘制测试；范围还没有来源的参数没有写死的上下限
- 色温和曝光的用户文件里是显示值

人工验收不能代替 T-12 到 T-20 里已经可以自动化的项。像素差异不作为回归失败理由，扣点和图层形状错了才是。

## 6. 审核时怎么判

1. 列出这次审查范围里的契约编号和 B 编号。
2. 找到带这些编号的测试，或指出没有测试。
3. 看运行输出。编译过了但测试没执行，不通过。
4. 抽一条失败路径，确认断言检查的是结果码和留下来的文件，不只是「函数没有抛异常」。

缺 T-01、T-02 或 T-03 的模块，打回补测试后再审，不把它记成功能已完成。
