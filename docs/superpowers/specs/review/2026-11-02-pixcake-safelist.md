# 安全清单（SafeList）

日期：2026-11-02  
状态：开工前合同  
总则：[审核总则](2026-11-02-pixcake-review-index.md)

桌面应用的输入来自登录框、搜索框、预设名、配方名、提示词、色值、快捷键、文件对话框、拖放路径、下发配置、第三方生成结果、IPC 和共享内存。审核时按本表逐项看这些入口。样例数据上没出事，不算通过。

## 1. 注入和查询

| 编号 | 检查 | 不通过 | 严重程度 |
| --- | --- | --- | --- |
| S-01 | SQLite 只使用参数绑定。项目名、文件名、搜索词、预设名、路径、任务编号都是绑定参数 | 用字符串拼接、格式化或拼接引号来组 SQL，包括「内部调试语句」 | 否决 |
| S-02 | 不把用户输入传给 shell 来移动、删除或打开文件 | 路径外面套一层 `sh -c`、`system` 或等价调用 | 否决 |
| S-03 | `.xmp` 按 XML 解析时禁用外部实体和外部 DTD | 默认解析器去拉外部实体 | 否决 |
| S-04 | CUBE、预设口令和配置 JSON 只按声明的结构读取 | 把配置里的路径或类名拿来动态加载代码 | 否决 |
| S-05 | 搜索和筛选在数据库或已加载索引里执行 | 把搜索词拼进查询后再解释成命令 | 否决 |

动态 SQL 如果必须存在，审核时要看到白名单字段，而不是看到拼接函数「目前只有一处调用」。一处拼接也是否决。

## 2. 输入、路径和文件

| 编号 | 检查 | 必须发生的事 | 严重程度 |
| --- | --- | --- | --- |
| S-06 | 预设名、配方名、项目搜索、提示词、HEX 和 RGB | 长度和字符范围在拥有该数据的模块里拒绝。界面校验不能代替内核或服务侧校验 | 否决 |
| S-07 | 导入是否可信 | 扩展名只做初筛。打不开、尺寸非法或内容对不上的文件按边界清单拒绝，不进入项目 | 否决 |
| S-08 | 导入的文件会不会被执行 | 图片、XMP、CUBE、素材只读数据。不根据文件内容启动程序，不把它们复制到可执行位置 | 否决 |
| S-09 | 导出目标路径 | 成品只换名到用户这次选定的目录，或需求写明的原始照片所在文件夹。临时文件只在 `cache/exports/`。规范化之后的路径不得用 `..` 写出这两个根 | 否决 |
| S-10 | 原图访问 | 只使用绝对路径和系统授予的书签或安全范围。不把任意路径的读取权扩成整个磁盘 | 否决 |
| S-11 | 从磁盘删除 | 只在明确命令且权限足够时删除那个源文件。权限不足时按 B-102，不扩大删除范围 | 否决 |
| S-12 | 解码 | 宽、高、行距先检查再分配。0、负数、溢出按 B-40、B-48 处理。不把预览最长边 4000 误当成「大图一律拒绝」的解码上限 | 否决 |
| S-13 | 共享内存和 IPC | 先校验长度、修订号、任务编号和结果编号，再读像素或落层。任务编号必须是本机账本里已有的任务 | 否决 |
| S-14 | 下发配置 | 点数和开关按契约 C-08、C-09、B-86 读取。不把配置里的 URL 或动态库路径拿来执行本机代码 | 否决 |
| S-15 | 快捷键自定义 | 只接受需求第 23 节允许自定义的命令。不可自定义的键不能被改写去触发别的命令 | 必须补 |

提示词会离开本机。发送前使用该工具参数模式里的长度上限。没有上限的，先补参数模式再调用远程，否则 S-06 不通过。

## 3. 第三方依赖和通用算法

| 编号 | 检查 | 不通过 | 严重程度 |
| --- | --- | --- | --- |
| S-33 | 通用能力已有合适的第三方库时，优先使用维护中的库 | 在生产代码里手写图像解码、编码、标准格式解析、压缩、密码学或通用 IPC，而没有全局依赖规范要求的候选比较和例外记录 | 否决 |
| S-34 | 第三方库来源、版本、许可证、传递依赖、平台支持和构建校验可追溯 | 下载来源不明、版本漂移、许可证未核对，或把未经审查的二进制直接放进应用包 | 否决 |
| S-35 | 第三方库只在拥有该能力的模块使用 | 为了方便把图像库、网络库或推理运行时直接塞进 `kernel/`，或让库绕过项目的结果码、路径和事务边界 | 否决 |
| S-36 | 运行时不下载和执行未锁定的依赖 | 启动时拉取 `latest`、动态加载配置指定的库路径，或库不可用时静默切换到未经验证的手写实现 | 否决 |

第三方依赖的选型、获取和手写例外按[全局依赖规范](../2026-11-06-pixcake-third-party-dependency-policy.md)记录。适配层、输入长度校验、任务生命周期和事务提交仍由项目代码负责。

## 4. 秘密和硬编码

产品默认点数、默认张数和工具包价格可以出现在 `services/config` 的默认数据里。它们不是密钥，但也不能散落在工具类里。这是契约 C-08，不是安全例外。

| 编号 | 检查 | 不通过 | 严重程度 |
| --- | --- | --- | --- |
| S-16 | 短信网关、对象存储、更新包、第三方工具的令牌和私钥 | 写进源码、测试快照、示例配置或仓库里的文档 | 否决 |
| S-17 | 会话、验证码、微信票据、商家密码、支付凭证 | 写进源码或为了方便调试做成默认账号 | 否决 |
| S-18 | 本地会话 | 退出登录只清会话，不把会话复制到日志、预设或项目文件里 | 否决 |
| S-19 | 预设分享口令 | 不当成可以长期写进 info 日志的普通字符串 | 必须补 |
| S-20 | 测试 | 测试账本不连接真实支付，不在仓库里放真实令牌。测试用的假令牌要看得出是假的 | 否决 |

发现仓库里已经有真实秘密时，这一关直接不通过。审核记录写文件位置，不把秘密再抄进审核记录。

## 5. 日志里不许出现的东西

架构第 6.1 节允许日志记路径，禁止记原图像素，也禁止记绝对路径以外的照片内容。本清单加上身份凭证。

| 编号 | 不许写入日志、崩溃转储或导出失败文案的内容 | 严重程度 |
| --- | --- | --- |
| S-21 | 原图像素、预览帧像素、生成结果像素 | 否决 |
| S-22 | 密码、短信验证码、会话令牌、微信登录票据、支付凭证、第三方鉴权头 | 否决 |
| S-23 | 照片内容本身，例如把人脸裁片、提示词里粘贴的隐私正文整段打出来。路径可以记 | 否决 |
| S-24 | 为了排错把整份精修文档或整份配置（含令牌）打进一条日志 | 否决 |

允许记：模块、结果码、任务编号、文档修订号、能力标识、字节数、耗时、路径、不含秘密的失败类别。

用户能看见的错误可以说明「验证码错误」或「点数不足」，不能把验证码原文或令牌回显到界面上。

## 6. 鉴权和记账

| 编号 | 检查 | 必须发生的事 | 严重程度 |
| --- | --- | --- | --- |
| S-25 | 未登录能碰到的入口 | 只有登录页和登录页上的帮助。项目、导出、生成、扣点、扣张都不可用 | 否决 |
| S-26 | 谁可以改余额 | 只有账本根据任务事件改点数和张数。按钮处理函数不能直接加减 | 否决 |
| S-27 | 谁可以接受用户命令 | 只有主进程的命令入口和 `kernel-cli`。导出进程、生成进程、渲染进程不接受那一组命令 | 否决 |
| S-28 | IPC 会不会被拿来白扣 | 一条「生成成功」或「请扣点」的消息，若任务编号不在本机账本、修订对不上或事件顺序不对，拒绝并不改余额 | 否决 |
| S-29 | 单实例 | 第二个实例不能打开第二套数据库，也不能绕过锁再扣一次 | 否决 |
| S-30 | 更新包 | 替换应用之前校验来源和完整性。校验失败不替换、不改项目库。本规范补齐：需求只写了下载、替换和重启 | 否决 |
| S-31 | 个人中心里的外部购买链接 | 用系统浏览器打开那个链接。不在应用里执行网页返回的脚本 | 必须补 |
| S-32 | 商家共享的工具包 | 共享范围是该商家成员。不因为本机缓存里有一次成功记录，就给另一个账号免校验地使用 | 必须补 |

内核库不读取窗口系统来判断「用户像是已经登录」。登录态来自账号服务和本机会话。界面把未登录隐藏掉，不能代替 S-25 的检查。

## 7. 过这一关时怎么抽查

至少打开这些位置往下读，而不是只搜函数名：

- `storage` 里执行语句的地方，确认没有拼接
- 导入、导出、删除源文件、换名提交的路径计算
- 登录和账号服务的日志调用
- 账本改余额的所有调用方
- 生成进程和导出进程的消息接收入口
- 仓库里是否出现密钥、令牌、真实手机号和验证码

任何一处命中否决项，结论是打回重写该入口。不接受「外层已经校验过，所以内层可以拼接」。
