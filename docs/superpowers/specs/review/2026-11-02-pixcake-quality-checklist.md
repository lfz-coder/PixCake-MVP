# 代码质量清单

日期：2026-11-02  
状态：开工前合同  
总则：[审核总则](2026-11-02-pixcake-review-index.md)

架构第 2 节的高内聚、低耦合、高鲁棒性是评审否决条件。这一关把它们收成可以逐行打的问题。风格偏好，例如空行和括号，不单独构成打回。

## 1. 命名

| 编号 | 检查 | 不通过 | 严重程度 |
| --- | --- | --- | --- |
| Q-01 | 模块目录、CMake 目标和架构第 5 节一致，目标前缀是 `pixcake_` | 一个目录里堆了两个互不相关的主人；目标名字看不出是哪一个模块 | 否决 |
| Q-02 | 能力标识与契约清单第 4 节一致 | 用临时拼音、中文或另一套英文标识写入用户文档 | 否决 |
| Q-03 | 显示名和标识分开 | 把界面上的「色温」当成存储标识，语言一变旧文档就读不出 | 否决 |
| Q-04 | 命令、编译、入队、记账能从名字看出各自的副作用 | 命令入口、能力编译或队列提交用 `process`、`handle`、`doData` 这类名字，调用方必须打开函数体才知道改的是文档、预览还是余额 | 必须补 |
| Q-05 | 结果码和状态使用契约里的语义 | 另造 `OK2`、`fail`、`status == 3` 这种叫法，调用方靠注释猜测 | 否决 |

公开头里的类型名要能让调用方不打开源文件就知道它做什么。做不到，就是架构第 2.1 节没通过，记否决。

## 2. 一个模块只有一个变更理由

| 编号 | 要改的事情 | 只应该改哪里 | 严重程度 |
| --- | --- | --- | --- |
| Q-06 | 某个滑杆的范围、步进或默认值 | 该能力的参数模式 | 否决 |
| Q-07 | 撤销如何折叠 | `history` | 否决 |
| Q-08 | 扣点和取消 | `ledger` 与配置数据 | 否决 |
| Q-09 | 导出临时文件如何提交 | `exportq` | 否决 |
| Q-10 | 图层混合 | `layerdoc` | 否决 |
| Q-11 | 窗口布局、菜单和快捷键显示 | Qt 壳，快捷键数据仍来自同一张表 | 否决 |
| Q-12 | 一个类既改文档又画控件 | 拆开。这是架构第 14 节要求人工看的两件事之一 | 否决 |
| Q-13 | 命令入口里出现色彩公式、SQL 或 OpenGL | 从命令入口移走。命令入口只做分发和门闩 | 否决 |

精修能力之间不互相 include。需要共用的蒙版、人物和路径升到内核模块，不从邻居能力里抄一份。

## 3. 注释

不要求给每个函数配一段复述代码的注释。参数模式、结果码和状态枚举本身就是说明。

| 编号 | 必须在保持该不变量的模块上写清楚的事 | 严重程度 |
| --- | --- | --- |
| Q-14 | 修订号只增。预览副本不写盘，也不能被导出取走 | 否决 |
| Q-15 | 用户文件存显示值。色温和曝光若有控件内部整数，换算不进文件 | 否决 |
| Q-16 | 排队中取消不扣，生成中取消不退，同一任务编号和笔触编号不双扣 | 否决 |
| Q-17 | 带 Free 的旧片段保留字节并跳过，不在本阶段注册绘制 | 否决 |
| Q-18 | 正式文件的五步替换。失败时留着上一份完整文件 | 否决 |
| Q-19 | 极速导出不因为队列空闲而自己关闭 | 否决 |

这些句子可以很短，但必须放在执行该规则的公开类型旁边。只写在某次审核聊天里，Q-14 到 Q-19 不通过。

注释若解释的是和契约相反的行为，例如「先存控件值，界面再换算」，这一行否决，并且回到契约关打回。禁止用注释把已知的合同违反说成临时方案。

## 4. 重复

| 编号 | 只允许有一个主人的数据 | 第二份出现在这里就不通过 | 严重程度 |
| --- | --- | --- | --- |
| Q-20 | 滑杆范围、步进、默认值、轨道颜色 | 控件子类里的常数 | 否决 |
| Q-21 | 蒙版部位名称和包含关系 | 各能力自己的一份枚举 | 否决 |
| Q-22 | 默认点数、张数、两套免点开关 | 工具类里的字面量 | 否决 |
| Q-23 | 快捷键表 | 菜单一套、自定义页一套、窗口再写一套按键 | 否决 |
| Q-24 | 手动网格和笔触 | 能力里再复制一份，而不是引用 `manual` 的增量 | 否决 |
| Q-25 | 文档字段 | IPC 再定义一套含义相同但名字不同的字段 | 否决 |

两段代码长得像，但变更理由不同，不强迫合成一个辅助函数。为了消灭重复把账本和导出队列焊成一个模块，是 Q-08 和 Q-09 的否决。

## 5. 过度设计

阶段一出现下面任何一种，就是否决。它们在架构第 3.1 节或第 17 节已经放弃。

| 编号 | 不要写 | 严重程度 |
| --- | --- | --- |
| Q-26 | 内置精修能力的热插拔动态库，或让能力自己创建 OpenGL 上下文 | 否决 |
| Q-27 | `pixcake::gl::native` 的绘制函数体。类型和方法可以冻结 | 否决 |
| Q-28 | 把表情、牙齿、眼睛、妆容、头发提前拆成五个库 | 否决 |
| Q-29 | 把云协同、工作流编排、联机拍摄会话、芝士交付写进内核协议 | 否决 |
| Q-30 | 把整条撤销链写入磁盘 | 否决 |
| Q-31 | 让导出任务跟随入队之后的新滑杆，以便「更实时」 | 否决 |
| Q-32 | 在界面进程里跑全分辨率导出或生成式请求 | 否决 |
| Q-33 | 为实现带 Free 的分组先把参数模式和着色器搭出来 | 否决 |

壳层上的后续阶段入口要在。未实现的深层能力显示为后续阶段，不做成已经完成的功能，也不做成点了没反应的死按钮。这是需求第 25 节，记必须补；若入口假装扣点成功或写出了假结果，升为否决。

## 6. 怎么和前几关一起看

质量问题若改变了参数、返回值或副作用，结论回到契约关，按打回重写处理，不单列成「以后再整理」。只是名字难懂、又不影响合同的，停在 Q-04 的必须补，补完才能算这一轮通过。
