# 语义抠图第三方依赖与模型选型基线

日期：2026-11-06  
状态：选型基线；2026-11-06 起 LiteRT、ONNX Runtime 与三个模型（MediaPipe ×2、BiSeNet）已进入生产构建（开关 `PIXCAKE_ENABLE_INFERENCE`），其余候选仍未批准  
2026-11-06 修订：用户确认 PixCake 不用于商用。许可门槛由“允许商业分发”改为“允许非商用使用与分发”；仍须遵守署名、研究/教育用途等具体条款，见 §2.2。

## 1. 目的与范围

本文记录人物、皮肤、头发、五官、衣物、宠物和背景蒙版所需的第三方模型、权重、推理运行时和部署依赖的当前状态。它是进入实现前的依赖基线，不把候选库、候选模型或用户界面名称误写成已经集成的能力。

本文覆盖：

- 人物与衣物语义分割；
- 人脸/五官和人物属性检测；
- 宠物与背景分割；
- 模型推理运行时和平台后端；
- 预览与全分辨率导出的模型一致性；
- 权重、训练数据、传递依赖和商业分发许可。

本文不覆盖：

- 项目自己的参数、图层、蒙版编号和历史格式；
- 通用图像 I/O 库的最终选型；
- 任何模型训练实现。

## 2. 当前结论

1. 本仓库不训练语义分割模型，不收录训练脚本，也不把某一组权重写成唯一实现。
2. 生产路径预期使用外部许可允许的预训练模型，由 `renderd` 和 `exportd` 负责推理；`kernel` 只保存蒙版编号、合并后的 alpha 图、加减关系、羽化和可见性。
3. BiSeNet ResNet18 ONNX 与 SCHP ATR 已在隔离环境完成 PoC，但尚未批准任何人物/衣物分割模型、权重、模型运行时或模型下载地址进入生产构建。
4. 当前唯一已经集成并锁定的第三方源码是 Glad OpenGL loader；它与语义抠图无关。
5. `libvips` 8.18.7 已有集成前锁定记录，服务于图像 I/O 候选方向，不是语义抠图模型，也尚未进入生产 CMake。
6. 在具体模型完成许可证、标签覆盖、平台和性能审计以前，代码不得把缺失部位用相邻部位冒充，也不得返回伪造 alpha 图。

## 2.2 许可门槛修订（2026-11-06）

用户确认项目不用于商用。因此：

- 非商用条款（如 CelebAMask-HQ 的非商业研究/教育条款、CC BY-NC 4.0）不再是否决理由；
- 仍须逐项记录并遵守：署名、许可证文本随包、“仅研究/教育”等用途限制、禁止用途（如监控、身份识别）；
- 若将来改为商用，本节失效，所有模型须按商用分发重新审计。

## 2.1 可运行的第三方候选（调查基线）

本节把“有候选可以跑”与“可以随产品发布”分开。候选可以用于独立样片验证；在许可证、权重来源和标签覆盖完成审计以前，不得进入产品包。

| 候选 | 能力 | 已知输出/运行方式 | 当前判断 |
|---|---|---|---|
| `yakhyo/face-parsing` BiSeNet | 脸部语义解析 | MIT 代码；提供 ResNet18/34 权重和 ONNX 导出/推理；19 类包含皮肤、左右眉、左右眼、耳朵、嘴、上下唇、脖子、头发、帽子等 | **最适合先做脸部样片 PoC**；牙齿、口腔、身体皮肤不能直接宣称已覆盖，权重与训练数据仍需单独审计 |
| `PeikeLi/Self-Correction-Human-Parsing`（SCHP） | 人体/衣物解析 | 官方仓库提供 LIP、ATR、Pascal-Person-Part 预训练模型；LIP/ATR 标签覆盖头发、帽子、手套、上衣、连体衣、裤子、裙子、鞋、包、围巾等 | **最适合先做人物/衣物样片 PoC**；官方仓库和权重的商业分发许可尚未完成核验，不能直接作为发布依赖 |
| ONNX Runtime | 模型推理运行时 | MIT 项目；提供 C/C++ API；Execution Provider 支持 CPU，CoreML、DirectML、CUDA 等后端；CoreML 文档当前标为 preview | **首选运行时候选**；先用 CPU 验证，再评估 macOS CoreML 和 Windows DirectML，版本和构建方式仍需锁定 |
| libvips | 解码、缩放和编码 | LGPL-2.1-or-later，项目已有 8.18.7 锁定记录 | **图像 I/O 候选**；不负责语义抠图，仍未集成 |

当前最可行的第一条实验链是：

`libvips（输入） → 人脸 BiSeNet / 人体 SCHP（ONNX） → ONNX Runtime（CPU） → 项目 alpha/标签适配器`

这条链可以先在独立样片工具中跑通，不需要先把模型运行时放进 `kernel`，也不要求一次覆盖全部 25 个部位。

## 4. 依赖分层

| 层 | 责任 | 当前状态 |
|---|---|---|
| 语义模型 | 从像素产生部位 logits/alpha | 未选型、未集成 |
| 模型权重 | 具体版本、下载来源和校验值 | 未锁定 |
| 推理运行时 | CPU/GPU/Metal/Core ML/其他后端 | 未选型 |
| 图像 I/O | 解码、缩放、编码、色彩输入 | `libvips` 是候选，未集成 |
| 项目适配层 | 标签映射、尺寸校验、alpha 合并、错误码 | 接口边界已规划，真实模型尚未接入 |
| 内核数据层 | 蒙版编号、引用、可见性、羽化和子蒙版 | 已有部分结构和测试 |

模型、权重和运行时的第三方头文件不得进入 `kernel/`。推理失败必须返回明确错误或不可用状态，不能在内核中生成替代像素。

## 5.1 官方候选核验结果（2026-11-06）

以下事实来自候选项目的官方仓库或官方文档，仍不等于 PixCake 已经完成集成：

- `yakhyo/face-parsing` 的 `v0.0.2` release commit 为 `5a8613c`；仓库提供 ResNet18/ResNet34 的 PyTorch 和 ONNX 权重下载入口、ONNX 导出脚本和 ONNX 推理脚本。仓库代码标注 MIT，但发布权重和其训练数据集的分发条款仍需单独保存和审计。
- `PeikeLi/Self-Correction-Human-Parsing` 官方 README 提供 LIP、ATR 和 Pascal-Person-Part 三套预训练权重入口；LIP/ATR 的标签覆盖头发、帽子、手套、上衣、连体衣、裤子、裙子、鞋、包、围巾等。当前没有在仓库内取得可供 PixCake 分发的权重校验值，也没有完成代码、权重和数据集许可证核验，因此只能作为隔离 PoC 候选。
- ONNX Runtime 官方仓库当前可核验的最新 release 是 `v1.30.0`（commit `f2c39fe`），代码许可证为 MIT；官方文档提供 C/C++ API 和 CPU、CoreML、DirectML 等执行提供者。`v1.30.0` 不是本项目已经批准的锁定版本，仍需在目标平台验证后再锁定。
- ONNX Runtime `1.30.0` 官方 macOS arm64 C/C++ 包已在隔离目录下载，包 SHA-256 为 `6ebb5062a934537c352937821f9fe9718e7de1a2db1122a93dd363ffd53a7012`，包内版本文件为 `1.30.0`，提交为 `f2c39fe2f838cf35ce7da92824f5a5e3ee6e88a7`。C++ smoke test 已加载 BiSeNet ONNX 并成功执行一次 CPU 推理；该包仍未写入项目 CMake。
- 该 C++ 包同时带有 `ThirdPartyNotices.txt`，包含 Intel MKL、protobuf 等传递组件的许可文本；如果将来进入产品包，必须把这些 NOTICE 纳入可复现的打包方案，不能只复制 ONNX Runtime 的 MIT 文件。

本节不把 GitHub release 的下载入口当作权重 SHA-256，也不把仓库代码许可证当作训练数据或模型权重许可证。两者必须分别取得证据。

## 6. 每个模型候选必须补齐的记录

在模型进入生产 CMake、打包脚本或运行时资源目录以前，必须为每个候选补一张记录，至少包含：

1. 官方仓库、论文或发布页；
2. 模型名称、版本/tag/commit；
3. 权重文件下载地址和 SHA-256；
4. 模型代码许可证；
5. 权重许可证；
6. 训练数据集名称、许可证和商业使用限制；
7. 模型卡中允许和禁止的用途；
8. 输出标签完整列表和 25 个项目部位的映射；
9. 未覆盖部位清单；
10. 输入尺寸、颜色空间、归一化方式和输出格式；
11. 推理运行时及其传递依赖许可证；
12. macOS、Windows 和鸿蒙的可用后端；
13. CPU/GPU/显存或统一内存要求；
14. 单张预览和全分辨率导出的耗时、峰值内存和最大尺寸；
15. 损坏输入、模型加载失败、超时、取消和资源不足的结果码映射；
16. 模型文件的安装、升级、回滚和离线分发方式；
17. 预览与导出是否使用同一模型、同一标签映射和同一合并规则。

## 7. 标签与合并规则

模型标签不能直接成为项目公开能力名。适配层必须维护一张版本化映射表，至少表达：

- 模型原始标签；
- 项目部位 ID；
- 是否是直接输出、多个标签并集或项目派生结果；
- 父子包含关系；
- 前景/背景冲突处理；
- 模型不输出时的不可用状态。

例如，`全部衣服`可以由已验证的衣物子标签合并，但不能因为模型没有“内搭”标签就把“上衣”复制为“内搭”。如果某个模型没有独立输出“眼白”，`眼白`必须保持不可用，直到另一个经过审计的模型或明确的派生算法被批准。

## 8. 进入实现的门槛

满足以下条件后，才可以实现真实语义分割适配器：

- 至少两个候选模型完成对比，或记录唯一可接受候选的理由；
- 许可证、权重、训练数据和传递依赖允许当前用途（非商用，见 §2.2）的使用与分发，具体条款已记录；
- 25 个部位逐项完成支持/不支持映射；
- 推理运行时版本和平台后端锁定；
- 模型文件有固定来源和 SHA-256；
- 预览/导出尺寸、性能和内存上限已测量；
- 损坏输入、超时、取消、模型缺失和资源不足已有测试替身；
- `renderd`/`exportd` 适配器不把第三方错误伪装为成功；
- `kernel` 依赖检查确认没有引入模型运行时或图像库；
- 模型资源、NOTICE 和许可证文本有可复现的打包方案。

## 9. 当前可继续推进的工作

在本基线未完成具体模型选型以前，可以继续完成：

- 蒙版编号、图层引用、密度、羽化和可见性；
- renderd/exportd 的解码、编码和推理接口契约；
- 项目索引、登录会话、IPC 字段、UI 结果提示；
- alpha 蒙版的尺寸、坐标、缺失资源和错误码校验；
- 参考渲染路径和测试替身。

不得把这些接口测试描述成真实语义抠图已经完成。
