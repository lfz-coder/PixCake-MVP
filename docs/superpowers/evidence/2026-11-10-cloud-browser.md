# 只读云目录页面与后台账号验证验收

日期：2026-11-10
对应：[CBR-01–06 计划与契约](../plans/2026-11-10-cloud-browser.md)。用户确认暂不选择短信供应商，先完成其余接入。

## 已实现

`BackendV1Codec` 增加 `/v1/account` 编解码；`query_directory` 先验证服务端账号和会话到期，再用独立的 AccountSession / CloudSession / CloudService 请求目录。身份、空间和项目共用最多 5 秒预算。既有账号必须与服务器结果相符；恢复凭证时账号 ID 由服务器提供，不接受文件自报身份。

`apps/shell/CloudClient` 在后台单任务中使用不可变输入；Qt 线程只负责账号、状态和 UI 回调，禁止跨线程共享可变会话。结果提交前再检查 generation；同凭证重登、退出和账号变化后的旧响应丢弃，凭证恢复也不能复活已退出的代数。网络错误保留完整旧目录，401/403/过期/身份不匹配清除目录权限，切换空间失败不会误标旧项目所属空间。

恢复竞争测试初次失败暴露了 `sign_out()` 在尚未登录时没有推进代数的问题。已修复为每次显式退出均使旧认证请求失效；已有 `StateConflict` 返回约定保留，并增加账号层与异步恢复层回归验证。

云空间成为主导航中的非项目页：个人/团队列表、可读权限、项目名称/修订/更新时间/字节数、刷新及状态提示。页面仅通过 PageActions 发意图；文案与状态在 ui/shell。新增视图依据已有产品功能需求，沿用主题，并不声称复刻未经观察的外部产品布局。照片传输尚未实现，页面明确说明仅浏览目录。

正式运行使用已有 ProcessLog，`cloud.directory.query` 只记录模块/事件/结果码，无令牌、账号、项目名、URL、游标或远端正文。后台任务退出前先停止回调；析构等待当前有界请求，不声称具备主动网络取消。API 未返回余额/订阅，不把开发恢复时的本地默认值当成服务端权益。

## 构建与测试

- Debug：HTTP ON、DEV_PAGES ON，完整桌面及 `pixcake_app_bundle` 构建通过，沿用 `-Wall -Wextra -Werror`。
- Release：HTTP OFF、DEV_PAGES OFF，桌面构建通过；发布参数拒绝 `--page` 与 `--dev-cloud-session-file`。关闭 HTTP 不下载/链接 JSON/curl 实现，仍显示未配置状态。
- `test_backend_v1_codec` 扩展账号字段、重复 key、坏数值、身份不匹配、过期和身份+目录预算。
- `test_cloud_client` 验证实际工作线程与 UI 回调线程不同、单任务限制、目录保留、权限清除、账号代数、恢复不能复活旧登录、析构释放及日志不含远端内容。
- `test_shell_display` 验证云页与主页/本地项目互通，未登录不可进入、云目录不能直接当本地项目打开；页面 smoke 验证实际控件存在。
- `architecture_gate`、云依赖正负样例、第三方依赖锁检查通过。应用包 MIT 文本 SHA-256 为 `46a65cffd1ea955132d95a8dd921640714a8d6b537d2e4e482d31145ae95b603`，与锁文件一致。

通过的专项集合：Debug 12 项（账号/云服务/网关/codec/curl/异步客户端/显示模型、登录与云页 smoke、云依赖、架构、第三方锁）；Release 10 项（账号/云服务/网关/客户端/显示模型/登录 smoke/两种开发参数拒绝/云依赖/架构）。后端 pytest 29 项通过，仍有已有的 Starlette 测试客户端 HTTPX 弃用提示。真实 TLS 集成使用独立临时数据库、证书与测试账号，不访问用户项目库、不启动助手侧进程、不修改钥匙串。

页面集成脚本先用服务器验证后的会话打开真实桌面云页，加载两个空间及三个项目，点击刷新后仍保留当前空间和目录；随后运行原 C++ HTTPS 传输/分页/撤权/限额/超时用例。开发令牌文件的符号链接、宽权限、超长输入和命名管道均拒绝，输出不含令牌。文件以非阻塞方式打开后检查普通文件属性，防止管道卡住界面。截图检查覆盖标题、选中的云导航、空间类型、三行目录及深色可读性；首次默认浅色列表背景已修复。
