# 已注册色彩子分组与颗粒的参考像素实现（2026-11-06）

对象：`gpu/render/src/render_executor.cpp` 的参考绘制，以及与之逐项对比的条件性 GPU 路径。renderd 和 exportd 都使用同一个 executor；GPU 不满足条件时回退 reference。用户 2026-11-06 决定先做已注册参数的像素实现，再补测未注册的分组。

## 来源说明

像素蛋糕没有公开这些调整的算法，本项目的公式都是**暂定**的：规则写在代码注释里，用测试钉住，不声称与像素蛋糕的结果一致。共同约束：

- 参数缺省时取参数模式的默认值（契约：参数模式是默认值的唯一来源），不在渲染器里另写一份。
- 每组在默认值处是恒等变换，并且先判断“是否偏离默认”再进入逐像素计算；没碰这些分组的文档逐位不变。
- 每个操作只读一次参数（`ColorGroups`、`Grain`），逐像素循环里不查表。

| 分组 | 规则（暂定） |
|---|---|
| 色阶（RGB 复合） | 输入黑/白拉伸、输出黑/白压缩，都按 0..255。灰场框是 −1..1（与 Photoshop 的 0.01..9.99 不同），映射为中间调伽马 10^灰场（0 不变，正值提亮中间调）。上排两框的最小间隔未测，不校验 |
| HSL | 八个色带中心 0/30/60/120/180/240/270/300°，色相落在相邻两带之间按线性权重（权重和为 1，无接缝）。色相 ±100 = ±30°；饱和度按 1+值 缩放色度；明亮度向白/黑移动最多一半余量，乘以像素饱和度（灰色不动） |
| 黑白配置文件 + 黑白混合 | 先取 Rec. 709 亮度（与 `luminance()` 同权重）；各色带的混合值按像素色度提亮/压暗该色相，灰色不变。黑白档下 HSL 不编译（参数模式禁用规则），所以只走这一支 |
| 可选颜色 | CMYK 可选颜色的形状：颜色目标按“主色领先量”（红/绿/蓝取 max−mid，青/洋红/黄取 mid−min），白/黑按与中灰的距离，中性按两端都接近中灰的程度。青作用于红通道、洋红于绿、黄于蓝；相对模式按已有油墨缩放，绝对模式直接加；黑色在三个通道一起加减油墨 |
| 颜色分级 | 阴影/中间调/高光是以亮度 0、0.5、1 为中心的三角权重，混合把半径从 0.5（混合 0）放宽到 1（混合 100）；全局处处为 1。每区按色相加去掉自身亮度的色度（不提亮），乘饱和度；明度最多移动四分之一。“平衡”未注册，不参与 |
| 颗粒（detail） | 晶格值噪声，格子大小随图像短边（≤4000 预览与全分辨率导出观感接近），粗糙度混入逐像素噪声，颗粒色彩把单色噪声混向分通道噪声；阴影/中间调/高光按亮度三角权重（半径 0.5）。按坐标确定，同一帧每次相同。颗粒效果为 0 时整步跳过 |

不画的：**色彩编辑器**三项偏移——目标颜色（吸管、范围）没有注册，偏移无作用对象；有非零偏移时给一条诊断“色彩编辑器还没有目标颜色参数，偏移暂不绘制”，滑杆保持禁用。**配置文件“质感”“基础”**需要配置文件资源，还没接入；下拉框里这两项不可选。

## 耗时（2026-11-06）

`tests/gpu/bench_reference_render.cpp`（不是测试，Release 构建手动运行），4000×3000（预览最长边上限）一帧，三次取最快，Apple M2 Pro：

| 情况 | 优化前 | 优化后 |
|---|---|---|
| 只有曝光（基线） | 1876 ms | 34 ms |
| 色阶 | 1977 ms | 45 ms |
| HSL | 2418 ms | 91 ms |
| 黑白 | 2568 ms | 71 ms |
| 可选颜色 | 2321 ms | 87 ms |
| 颜色分级 | 2057 ms | 62 ms |
| 全部色彩分组 | 3930 ms | 175 ms |
| 颗粒 | 301 ms | 46 ms |

慢的主要是原有代码，不是新分组：白平衡、影调每个像素在 `std::map` 里查约 20 次参数，并逐像素重算白平衡矩阵；合成每个像素比较混合模式字符串。改为每个操作读一次（`ToneColor`，白平衡矩阵和曝光增益也只算一次），混合模式换成枚举，再把行分给各核（`for_rows`，26 万像素以下单线程；每个像素只由所属的行读写）。浮点运算和顺序不变，逐像素结果一致：白平衡、对比度的金向量和全部像素测试照旧通过。

全部色彩分组同时打开时一帧约 175 ms，拖动时大约每秒 5～6 帧；只动影调约 30 帧。

## 着色器（2026-11-06）

`gpu/render/src/shader_sources.hpp`：全局色彩（白平衡、风格、影调、色阶、黑白/HSL、可选颜色、颜色分级）一个片元着色器，颗粒一个。每个函数逐行对应参考公式，常量和运算顺序相同；用 `texelFetch` 取像素（不过滤），写回 RGBA8，两张纹理来回绘制，所以每个操作之后都量化到 8 位，与参考逐操作写回一致。颗粒的格点坐标两边都改为乘以 1/格子大小（乘法在 CPU 和 GPU 上舍入相同，除法不一定）。

`RenderExecutor::execute` 现在接受多个操作：满足能力、通道、混合模式和蒙版数量门槛时走 GPU，否则整帧回退 reference。状态和诊断由两条路径共用的准备步骤产生，结果以本项目 reference 为基准。程序编译一次，两张帧纹理只在尺寸变化时重建（每个上下文一个执行器）。预览和导出都使用这条选择逻辑。

renderd 第一次绘制时建原生离屏上下文（架构 9.3：预览上下文在渲染进程里），建不出来或某次 GPU 绘制失败就改用参考，并给一条诊断。`PreviewResult::drawn_on_gpu` 记录这一帧是谁画的。

读回对比（`test_gpu_backend_C57_C60`，97×61 帧，含各色相、灰色、暗部亮部和半透明）：影调、色阶、颜色分级、颗粒、全局色彩+颗粒两步逐位相同；HSL、黑白、可选颜色最多差 1（浮点舍入，23668 个通道中分别有 281、3、47/43 个差 1）。变异检查：分别关掉色阶、黑白、HSL、可选颜色、绝对模式、颜色分级色调、影调提亮、颗粒，各自那一项失败，恢复后通过。

### 蒙版、混合、图层、局部与 AI 色彩（2026-11-06）

着色器改为“公共前段 + 主体”：公共前段是操作的合成（参考的 `composite()`）——一张 RGBA 蒙版纹理的四个通道最多装四个蒙版，相乘得到权重，再按像素透明度做正常、正片叠底或滤色混合。全局色彩着色器加了步骤开关（色彩一步、影调一步，与 `PreparedOperation` 相同），所以局部调色、后期调色、AI 追色、AI 色彩风格共用它；色彩子分组只在全局工具里打开。图层另有一个着色器（不透明度 × 图层蒙版）。图层的状态和诊断与操作一样由共用的准备步骤产生。

仍整帧回退参考的：3D LUT 滤镜、一个操作超过四个蒙版、门槛表之外的非零参数。

读回对比新增 8 种情况：局部一个蒙版、三个蒙版+正片叠底、后期四个蒙版+滤色、AI 追色与风格（风格带蒙版）、全局+带蒙版局部+颗粒三步、三层图层（含隐藏层，带/不带蒙版，三种混合）叠在全局色彩上、只有图层、五个蒙版（应回退参考）。前七种中蒙版和 AI 色彩逐位相同，图层两种最多差 1；第八种确认走了参考。变异检查：蒙版权重、第三个蒙版、正片叠底、滤色、图层蒙版、图层不透明度、影调开关、色彩开关各自关掉，对应情况失败，恢复后通过。

调试中踩到一处：上传纹理会把它绑到当前活动的纹理单元，先绑后传会把刚绑好的图层纹理换掉——现在一律先上传、后绑定。

4000×3000 一帧：带一个蒙版的局部调色参考 34 ms → GPU 25 ms；再叠一层带蒙版的滤色图层 53 ms → 34 ms（多一次 48 MB 上传和一遍绘制）。

未做：3D LUT 着色器（门面层没有 3D 纹理）；GPU 不满足条件时的导出仍回退 reference；源纹理没有跨帧保留（每帧上传约 1～2 ms）。这些结果仍不能证明与 PixCake 官方公式或色彩管理逐像素一致。
