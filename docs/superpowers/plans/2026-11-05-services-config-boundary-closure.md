# Services 配置缓存边界闭环计划

日期：2026-11-05

## 背景和审计结论

复审 C-08、C-09 和架构第 6.11 节要求：点数、张数、工具包价格和免点排队策略来自
配置缓存；没有缓存时使用需求第 17 节与附录 A 的默认表。官方工具免点队列与已订阅
工具包的非高算力免点队列是两套独立开关，9.3.0 的默认行为是前者关闭、后者开启。
错误配置不能被当成零点或零价继续使用。

当前仓库没有 `services/config`。本计划只实现配置数据、默认表、校验和内存缓存替换，
不做登录、网络拉取、支付、UI 设置或账本扣费。默认文字和数值全部取自需求文档，不补
文档未给出的价格或模型信息。

## 实现任务

### Task 1：冻结配置数据模型和校验 `[x]`

- 新增两套独立免点策略、官方加速规则、工具包年费和附录 A 第三方点数规则。
- 规则编号为空、重复、收费规则点数为零、免费规则带非零点数、套餐/工具价格为负时拒绝。
- 高算力标记只来自配置；四个“专业生图”条目按附录 A 标为高算力。

### Task 2：录入需求默认表 `[x]`

- 默认客户端版本为需求对照版本 `9.3.0`。
- 官方免点队列默认关闭，已订阅工具包的非高算力免点队列默认开启。
- 官方加速表、12 个工具包年费和第三方工具点数逐项使用需求原文数值。

### Task 3：实现缓存失效和替换语义 `[x]`

- 无缓存时返回默认表并标记 `used_defaults`。
- 缓存或下发配置校验失败时返回状态冲突，保留上一个有效快照，不把坏值改成零。
- 有效配置替换是整体操作，调用方始终读取同一份快照；模块不进行网络或磁盘 I/O。

### Task 4：测试、门禁和证据 `[x]`

- 覆盖两套开关互不合并、默认版本行为、官方免费/收费规则、第三方高算力标记、坏配置保留旧值。
- 新模块保持无 Qt、无 OpenGL、无网络和无账本实现依赖。
- 更新计划与证据，执行全量 CTest 和 `git diff --check`。

## 验收条件

- 默认快照能查到需求表中的官方加速、套餐和第三方点数；9.3.0 两套策略值正确。
- 无缓存和坏缓存都有明确结果；坏缓存不会产生零点或零价。
- 全量 CTest、架构依赖门禁和 `git diff --check` 通过。

## 明确不在本阶段

账号登录、网络配置下发、支付与订阅同步、账本扣费、生成服务调用、素材下载和 UI 设置
继续保持在后续计划。
