# Kernel 素材索引边界闭环计划

日期：2026-11-05

## 背景和审计结论

架构第 6.13 节规定，素材模块负责样片、CUBE、天空、证件照背景、布景和水印的编号、
分类和上限；精修文档只保存素材编号。样片库最多 2000 张、单次导入最多 1000 张，
超出部分必须拒绝并说明先删除。原文件丢失时保留编号，能力变为不可用，不能静默清掉
引用。

当前仓库没有 `kernel/assets`。本计划只实现内存索引、上限校验和可用性事实，不做文件
下载、缩略图、网络同步、素材像素解码或 UI 管理页面。

## 实现任务

### Task 1：冻结素材记录和类型 `[x]`

- 新增样片、CUBE、天空、证件照背景、布景和水印类型，以及编号、分类、来源路径和可用性。
- 编号和分类标识拒绝空值、NUL 和重复编号；文档侧只需保存素材编号。

### Task 2：实现导入上限 `[x]`

- 样片单次导入超过 1000 张直接拒绝；加入后总数超过 2000 张直接拒绝且不产生部分写入。
- 其他素材仍使用同一编号校验，但不把样片上限误套到其他类型。

### Task 3：实现缺失文件语义 `[x]`

- 文件检查只更新可用性，不删除索引记录或素材编号。
- 查询返回不可用事实和原记录，调用方据此置灰能力；模块不伪造文件恢复。

### Task 4：测试、门禁和证据 `[x]`

- 覆盖六类素材、空/重复编号、1000/2000 上限边界、超限无部分写入和缺失保留。
- 新模块保持无 Qt、无 OpenGL、无网络、无像素解码和无数据库依赖。
- 更新计划与证据，执行全量 CTest 和 `git diff --check`。

## 验收条件

- 有效素材可按编号和分类读取；样片上限严格为单批 1000、总量 2000。
- 文件缺失后记录仍在但 `available` 为假；超限请求不会静默截断。
- 全量 CTest、架构依赖门禁和 `git diff --check` 通过。

## 明确不在本阶段

素材文件下载、缩略图、远程同步、像素解码、UI 管理、精修文档写回和素材实际渲染继续
保持在后续计划。
