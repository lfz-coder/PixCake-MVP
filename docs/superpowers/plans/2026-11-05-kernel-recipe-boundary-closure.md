# Kernel 创意配方边界闭环计划

日期：2026-11-05

## 背景和审计结论

架构第 6.13 节规定，配方只描述有序的生成工具节点和可编辑参数；执行、扣点和取消
由账本与生成进程负责。批量设计进行中的图片由配方模块标记为占用，图层和历史命令
据此拒绝编辑。当前仓库没有 `kernel/recipe`，但 `layerdoc` 和 `history` 已接受批量
占用事实作为状态冲突输入。

本计划只实现配方编辑数据和批量占用表，不调用生成服务、不估算点数、不修改图层或
历史文档、不实现 UI 拖动排序。

## 实现任务

### Task 1：冻结配方与节点数据 `[x]`

- 新增配方编号、名称、节点编号、工具编号和不透明参数快照。
- 节点按加入顺序保存，节点编号和工具编号不能为空且不能重复；参数由生成任务解释。
- 配方允许先创建后添加节点，但开始批量执行前必须至少有一个节点。

### Task 2：实现节点编辑 `[x]`

- 支持追加、按编号删除和移动节点；非法编号、重复编号和越界位置返回状态冲突。
- 节点的 `editable` 只作为 UI/调用方事实保存，配方不解释参数内容。

### Task 3：实现批量占用生命周期 `[x]`

- 开始运行时绑定配方编号和非空图片编号列表，去重并拒绝已被其他批次占用的图片。
- 运行中的图片可查询为占用；完成或取消释放占用，重复结束和未知图片返回状态冲突。
- 配方模块不改变账本、图层、历史或编辑文档。

### Task 4：测试、门禁和证据 `[x]`

- 覆盖节点顺序、移动/删除、空配方拒绝执行、重复占用和完成/取消释放。
- 新模块保持无 Qt、无 OpenGL、无网络、无账本和无生成进程依赖。
- 更新计划与证据，执行全量 CTest 和 `git diff --check`。

## 验收条件

- 配方节点顺序和参数快照可完整读取；执行前没有节点会被拒绝。
- 批量运行期间图片占用事实稳定，完成/取消后可再次运行；不修改其他文档模块。
- 全量 CTest、架构依赖门禁和 `git diff --check` 通过。

## 明确不在本阶段

点数报价、远端生成、结果落层、UI 编辑器、官方配方清单、素材下载和持久化继续保持
在后续计划。
