# Kernel AI 挑图边界闭环计划

日期：2026-11-05

## 背景和审计结论

需求第 15 节和架构第 6.13 节规定，挑图模块保存场景、检测档位和打标结果，只写图片
标记，不写精修滑杆。检测可由渲染进程或生成进程完成；内核收到按检测器排序的决策后，
负责入选数量上限、标记目标和“保留已有标签”语义。现有项目库已有星级、色标、旗标的
写入边界，但没有独立的 `kernel/cull` 会话。

本计划只实现挑图规则与检测决策的内存边界，不实现人脸/美学/曝光/模糊/重复模型，
不直接写项目库、不改精修文档、不做 UI 或进程通信。

## 实现任务

### Task 1：冻结场景、检测档位和标记目标 `[x]`

- 新增通用、人像、证件照、活动、婚礼、家庭、儿童、学校、孕妇、私房十种场景。
- 新增弱/标准/强检测档位、星标/色标/旗标目标，以及保留已有标签和入选数量上限。
- 规则只保存检测器使用的事实，不在内核猜测阈值。

### Task 2：接收有序决策并应用边界 `[x]`

- 检测器按排序顺序提交每张图片的入选决策、重复分组和已有标签事实。
- 数量上限只保留前 N 个入选决策；保留已有标签时跳过对应目标的写入。
- 图片编号为空或重复、会话已结束和无效规则返回状态冲突。

### Task 3：完成和结果快照 `[x]`

- 完成返回场景、档位、每张图片的决策/分组和标记动作，取消丢弃未完成会话。
- 结果只包含标记动作，不包含精修参数或像素数据。

### Task 4：测试、门禁和证据 `[x]`

- 覆盖十种场景、档位/标记规则、数量上限、保留标签、重复图片和取消语义。
- 新模块保持无 Qt、无 OpenGL、无网络、无模型运行时和无项目存储依赖。
- 更新计划与证据，执行全量 CTest 和 `git diff --check`。

## 验收条件

- 挑图结果只产生图片标记动作，数量上限和保留标签规则可复验。
- 取消不返回结果；检测模型未实现时仍可由外部提交有序决策，不编造检测结论。
- 全量 CTest、架构依赖门禁和 `git diff --check` 通过。

## 明确不在本阶段

人脸、表情、美学、曝光、模糊、重复检测模型，项目库写入、UI、进程通信和精修参数继续
保持在后续计划。
