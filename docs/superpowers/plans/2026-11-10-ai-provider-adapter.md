# AI 生成服务适配层实现计划

日期：2026-11-10
状态：除真实官方协议外已完成；provider-neutral 主链路、工具目录、参数面板、生成进程恢复、结果落层、持久化历史、图层预览/全分辨率导出合成和失败重试均已完成；真实官方协议仍待接入

## 目标

为 PixCake 的官方和第三方 AI 工具建立一个与供应商协议隔离的生成适配层。PixCake 内核只认识稳定的 `GenerationTask`、`RemoteReply`、任务账本和图层结果；HTTP、SDK、认证、轮询、响应字段和供应商错误都留在适配器边界内。

## 约束

1. 不把猜测的官方 URL、JSON 字段、模型名或认证方式写成生产协议。
2. `kernel/` 不依赖 HTTP、Qt、OpenGL、JSON 库或推理运行时。
3. `apps/generated` 不写图层文档，不直接扣点；它只调用远端工具、校验结果、写结果文件并报告账本事件。
4. 结果落层由主进程通过 `layerdoc` 完成，并以结果编号去重。
5. 外部协议变化只能影响 `services/net` 和生成适配器；只有外部能力超过现有内部协议时，才修改 `GenerationTask`、IPC 或 `RemoteReply`。
6. 所有外部等待必须有超时；网络错误、供应商错误、取消和损坏结果都要转换成明确的 `ResultCode`。

## 分阶段计划

### 阶段 1：冻结边界（已完成）

- 建立 `services/net` 的 HTTP 传输抽象：请求、响应、请求头、超时和传输结果。
- 把 `RemoteReply`/`RemoteTool` 从生成服务中分离成稳定的 provider-neutral 接口。
- 建立 `GenerationWireCodec` 抽象，负责内部任务到外部请求、外部响应到 `RemoteReply` 的转换。
- 实现 `HttpRemoteTool`：只负责编排 codec 与 transport，不知道任何供应商字段。
- 用 fake transport 和 fake codec 测试成功、传输失败、编码失败、解析失败、非 2xx 响应和超时参数传递。
- 增加明确标注为非官方的 `FixtureWireCodec`，让本地测试能跑通编码、传输、解码、账本和结果文件全链路。

### 阶段 2：任务契约补全（第一版已完成）

- 在不让 `kernel` 依赖网络的前提下，为生成任务增加版本化的参数、选区/蒙版引用、参考图引用和幂等键。（已完成第一版不透明载荷和校验）
- 规定多结果、继续编辑参数、结果形状和结果校验的统一格式。（已完成：`RemoteResult`、结果列表和 `GenerationResultInfo`）
- 扩展 IPC，使提交、进度、取消和结果确认可以表达异步远端任务。（已完成提交、结果确认和带结果列表的进度编码）
- 保留旧文档字段，未知参数按现有文档兼容规则透传。

### 已落地的异步执行链路

- `GenerationServer`/`GenerationClient` 使用现有 Unix `Channel` 传输提交、进度、取消和结果确认消息。
- `pixcake_app_generated --fixture --socket ... --data-dir ...` 可以启动一个本地 fixture provider 生成进程；它不冒充官方服务。
- `GenerationResultApplier` 在主进程边界校验结果文件、RGBA 尺寸和 FNV 校验和，再以结果编号去重落入 `LayerDocument`。
- `GenerationFlow` 串起提交、验证、落层和确认，继续编辑参数随图层文档保存。
- `GenerationProcess`/`GenerationSession` 封装子进程生命周期、共享账本、报价/排队和重载；壳层可以只提交一个 provider-neutral `GenerationTask`。
- generated 服务在独立 worker 中执行 provider 调用，主通道仍可接收取消；取消后迟到像素不会发布，也不会追加成功事件。
- 开发构建的创意页 AI 入口已经接到明确标记的本地 fixture，图层文档保存到项目文档目录；发布构建仍拒绝猜测官方 provider。
- `ToolCatalog` 保存 provider-neutral 的工具标题、分类、参数模式、结果形状、输入能力和计费规则 ID；generated 路由从目录注册 adapter，Creative 页显示目录和最近任务。
- 主进程启动时把遗留的“生成中”任务折叠为失败；子进程启动失败和退出后的账本状态可恢复，Creative 页提供失败重试入口；重启后从 PXGH 历史解码参数、蒙版和参考图引用后仍可重试同一源修订。

### 阶段 3：官方协议接入

- 收到官方开发者文档或授权测试环境后，新增官方 wire codec。
- 把真实的认证、上传、提交、轮询、取消、下载和错误字段写入 `services/net`/适配器，不改账本和图层规则。
- 用录制的脱敏响应做契约测试；不把真实凭证、原图或供应商私有模型文件提交到仓库。

### 阶段 4：第三方工具包路由

- 配置把 `tool_id` 映射到 provider、endpoint、参数模式、计费规则和结果形状。
- 第三方工具仍复用同一 `GenerationTask` 和 `RemoteTool`，不为每个工具写一套生成进程。
- 搜索别名、创作者工具包和高算力标记只来自配置。

### 阶段 5：主进程落层与创意 UI（主链路已接入，基础工具目录 UI 已接入）

- 主进程消费生成进度，验证结果文件和校验和，调用 `layerdoc::place_result()`；图层文档同时保存像素路径、尺寸和校验和，renderd 重启后重新校验并合成到预览。（已接入现有 shell/controller）
- 导出任务同时快照精修文档和图层文档，exportd 在全分辨率路径验证生成像素文件、按目标尺寸确定性放大并交给同一套 reference/GPU 合成器；SQLite 事件日志和重启恢复保留图层快照。
- 生成结果支持新图层、图层组、细节层/效果层、可编辑蒙版和可变换图层。
- 已接通创意页 AI 入口、fixture 任务、图层文档路径、工具目录、工具选择、文本/数字/枚举/布尔参数编辑、持久化最近任务、生成状态和失败重试；失败重试会保留工具、参数、蒙版/参考图和源修订号，源图变化时拒绝重放；生成结果可从创意页经过命令入口写入精修文档并进入精修页继续查看和编辑。精修文档记录效果已烘焙、清掉可编辑滑杆，创意层文件继续作为已校验的预览像素来源。
- 创意页直接生成也走可取消后台 worker；源图切换、取消、图层快照损坏或落层失败时会拒绝并回收 provider 已写出的结果文件，避免阻塞 UI 或遗留孤儿像素。
- 线程已完成但 Qt 回调尚未执行时，关闭窗口或切换源图会在回调生命周期失效前回收待确认结果；精修页冒烟检查也会先清理页面重建留下的延迟删除节点。

### 阶段 6：端到端验收

- 使用 fake provider 验证无网、超时、重复回调、迟到结果、取消、生成进程崩溃、重复落层和恢复。
- 在官方测试协议可用后做真实沙盒测试；验证点数只由账本结算，UI 不直接修改余额。
- 记录协议版本、工具版本、结果校验和、诊断码和脱敏请求摘要。

## 当前实现边界

本阶段故意不实现真实 HTTP 客户端，也不猜测官方 API。`HttpRemoteTool` 的 transport 和 codec 都是可注入接口，因此现在可以完整测试生成进程的边界；官方协议确定后只需实现对应 codec/transport。当前 fixture 响应支持多结果、继续编辑参数、子进程取消、持久化历史、图层像素预览、全分辨率导出合成、命令入口应用至精修和创意页到精修页入口，但仍明确标为非官方协议。应用动作复用现有精修文档的“效果已烘焙”语义，创意像素由带校验的图层资源同时供预览和导出使用。
