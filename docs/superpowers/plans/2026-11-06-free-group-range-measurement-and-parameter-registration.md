# Free 分组范围实测与参数模式注册 Implementation Plan

日期：2026-11-06
状态：本阶段收口（2026-11-05）：已注册色阶、HSL、颜色分级、可选颜色、颗粒、色彩编辑器偏移、创意色彩程度；其余分组按用户裁定暂缓
基线：`1e9e479`

## Goal

依据需求、约束、设计文档、已有实测证据和官方桌面版手册，完成剩余 11 个 Free 分组及创意色彩“程度”的界面范围实测；每组形成可复核证据；只有规则完整且来源明确的参数才注册到 `kernel/capability` 参数模式，并用测试和复审记录固定结果。

## Constraints

- 只使用 `/Applications/pixcake-test.app` 9.3.0 的真实界面和 Jarvis AX 观测；不能凭常识补范围、默认值、步进或参数名称。
- 需要输入数值时，优先 AX；AX 对 `AXIncrementor` 无法写入时，按用户已授权的真实键鼠测量流程操作，操作前后按坐标重新观察，不使用固定 index。
- 每个被测控件必须恢复到原值；每组结束用 AX 读回并记录。
- 先查官方手册对应页面；手册没有写数字规则时，实测结果才能作为来源。手册没有给出名称或语义时，证据只使用位置/原界面文字，不命名推断。
- 上下限用越界测试和二分收敛；互相约束的控件必须记录约束关系和尚未确定的边界，不能提前注册。
- 曲线、HSL 等非数值控件只记录可观察的通道、节点或编辑语义；读不到的规则保留为未确认。
- 不引入第三方依赖，不修改需求、架构或清单以迁就实现；Glad 复现另立任务，未获安装权限前不执行安装。
- 每组完成后先写 `docs/superpowers/evidence/2026-11-06-free-group-<slug>-measurement.md`，再决定是否能进入参数模式。

## Rulings

- 参数标识（`parameter_id`）不在契约冻结范围内，由本项目选定并写在注册表注释里；能力标识仍按契约 §4。
- 色阶上排两框：与下文“注册门槛”第一条不同，已按各自 0..255 注册（`levels_rgb_output_black/white`）；两框之间的互相约束（最小间隔）未测、未校验。代价：用户可以在本项目里填出官方会拒绝的组合，补测后需要加一条约束校验。
- 颗粒能力：新增 `grain`，管线位于 `color.post` 之后、`manual.liquify` 之前（用户裁定其为独立能力，位置由本项目选定）。

## Per-group procedure

1. 用官方手册和 Jarvis 页面图确认入口、控件名称和语义。
2. 进入目标面板，记录初始 AX 树、数值、可见状态和控件坐标。
3. 对每个数值控件测默认值、可接受下限、可接受上限、拒绝值、显示精度和步进；对耦合控件记录约束矩阵。
4. 对非数值控件记录通道、枚举项、节点和可编辑动作；无法由 AX 或手册确认的内容写明“未确认”。
5. 恢复所有改动，截图或 AX 读回核对。
6. 写证据文件并标注“可注册 / 不可注册 / 待补测”。
7. 仅对“语义、范围、步进、默认值和禁用规则都已有来源”的参数编写失败测试、实现注册、运行相关 CTest 和 `git diff --check`。

## Registration gates

- 色阶上排两个输入框的最小间隔仍未测完，因此暂不注册这两个框；已有下排黑场/灰场/白场证据也不改名，直到需求 §10.3 或手册确认输入/输出语义。
- 手册给出的范围可直接作为来源；手册只描述方向、没有数字时，必须实测后才能注册。
- 步进未测定时设置为待确认，不写整数步进假设；默认值未确认时不写默认值。
- 任何 `Free` 分组不得因为标签而跳过实现，也不得因为界面存在就把未确认范围当作已完成。

## Validation and reporting

- 每个注册批次：对应单元测试、全量 CTest、架构门禁、`git diff --check`。
- 全部测量结束后更新总证据，列出已注册、待补测和明确未实现项。
- 最终报告包含：完成的测量与实现、测试结果、未解决的不确定性、下一步操作；不把手册未写或 AX 读不到的内容写成完成。
