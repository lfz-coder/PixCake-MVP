# Kernel 人物检测与属性边界闭环计划

日期：2026-11-05

## 背景和审计结论

架构第 6.7 节规定，`subject` 是人脸框、人物属性和跨照片同一人的只读人物视图主人。
年龄性别修改产生的覆盖值也归它管理；检测缓存可以重建，但重新检测不能丢掉已有覆盖。
检测未完成时，人像能力必须得到“不可用”，不能编造几何。单人调整提交后，属性调整不再
生效；恢复原人物属性时，单人锁和覆盖一起清掉。

当前仓库没有 `kernel/subject`。本计划只冻结检测快照、属性覆盖和单人调整锁的内核数据，
不接模型、不训练权重、不生成几何、不写 `EditDocument`，也不实现 UI 的年龄性别弹窗或
跨照片同步命令。

## 实现任务

### Task 1：冻结人物视图和检测状态 `[x]`

- 新增人物属性、年龄/性别覆盖、人脸框、人脸记录和检测状态类型。
- 人脸编号、图片编号、同一人编号和框坐标执行有限值与唯一性校验。
- `Pending`/`Failed` 状态不暴露人脸几何；`Ready` 快照允许没有人脸，表示本图没有可用人脸。

### Task 2：实现检测快照替换和覆盖保留 `[x]`

- 重新检测只替换可重建的人脸缓存，按稳定人脸编号保留年龄性别覆盖和单人锁。
- 不允许跨图片写入快照、重复人脸编号、非法框或在不可用状态写入人脸。
- 同一人编号只作为只读关联字段保存，不在内核里猜测识别结果。

### Task 3：实现属性覆盖与单人调整规则 `[x]`

- 只允许对 `Ready` 且存在的人脸设置覆盖；单人调整锁定后拒绝新的属性覆盖。
- 恢复原人物属性同时清掉覆盖和单人锁，使后续效果重新跟随属性。
- 提供只读的“属性是否适用”事实，供人像能力查询，不在 `subject` 内实现人像效果。

### Task 4：测试、门禁和证据 `[x]`

- 覆盖检测未完成不可用、几何校验、重新检测保留覆盖、单人锁、恢复和跨图片拒绝。
- 新模块保持无 Qt、无 OpenGL、无网络、无模型运行时和无文档写盘依赖。
- 更新计划与证据，执行全量 CTest 和 `git diff --check`。

## 验收条件

- 检测未完成时不返回任何人脸几何；检测成功后只返回已验证的快照。
- 重新检测不丢匹配人脸的覆盖值；单人调整后属性不再适用，恢复后重新适用。
- 全量 CTest、架构依赖门禁和 `git diff --check` 通过。

## 明确不在本阶段

真实人脸/属性模型、跨照片识别算法、年龄性别 UI、批量同步、像素渲染、文档写盘和人物
能力参数编译继续保持在后续计划。
