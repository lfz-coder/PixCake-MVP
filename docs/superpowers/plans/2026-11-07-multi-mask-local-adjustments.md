# 多蒙版局部调整：编辑文档里怎么存（方案，待确认）

状态：方案，未实现。文档格式一旦写进用户文件就要长期兼容，所以先写出来确认再改。依据：`docs/superpowers/evidence/2026-11-07-gradient-mask-observation.md`。

## 要解决的问题
官方的“蒙版列表”里一张照片有多个蒙版，**每个蒙版有自己的一整组调整滑杆**，一个蒙版内可以有多个子项（语义部位、渐变、画笔等）按添加/减去组合，底下有固定的“全图”。现在 `color.local` 只有一组参数、一个作用部位（`region`），一张照片只能有一个局部调整。

## 现状里的约束（已核对）
- 编辑文档按能力存片段，片段内是“参数编号 → 显示值”的记录；未登记的参数编号被当作未知字段原样保留。
- 参数编号只在少数几处被解析：`find_parameter_mode`（`capability_registry.cpp`），以及调用它的 `capability_module.cpp`（读取、写入、编译）、`preview_coordinator.cpp`（预览请求校验）、`preview_session.cpp`、`export_charge.cpp`（计费）、`slider_spec.cpp`（面板）。历史、预设、复制粘贴、批量同步、撤销都只搬“能力 + 参数编号 + 显示值”，不关心含义。
- 局部调色已经计入收费功能（已实测）。

## 方案：实例前缀参数（推荐）
`color.local` 的参数编号允许带实例前缀 `m<N>:`，例如 `m2:exposure`、`m2:region`。

1. **兼容**：没有前缀的参数仍然是实例 `m0`（现有文档不用迁移，行为不变）。
2. **登记**：不为每个实例登记一遍参数。`find_parameter_mode` 对 `color.local` 先去掉 `m<N>:` 前缀再查基础参数；前缀必须是 `m` 加 1 到 3 位数字，实例编号上限 32。其余能力不受影响。
3. **实例元数据**：新增两个登记参数：`name`（蒙版名称，文本，默认“自定义-N”）和 `combine`（子项组合，见下）。实例存在 = 片段里有它的任意参数。
4. **编译**：模块按实例分组，每个实例产出一个绘制步骤，顺序在基础顺序上按实例编号递增（`order + N/1000` 的整数等价写法），后一个实例画在前一个之上；每个步骤带这个实例的蒙版。`m0` 仍排在最前。
5. **子项**：一个蒙版里的多个子项（语义部位、线性渐变、径向渐变……）用 `m<N>:part<K>` 这一类参数表示：`region`、`gradient_*` 现在是“一个子项”的参数，扩展成 `m<N>:s<K>:region`、`m<N>:s<K>:gradient_x` 等；每个子项再有 `mode`（`add` 或 `subtract`）。渲染器现在每个绘制步骤最多四块蒙版，并集/差集要么先在 `gpu::add_gradient_masks` 里合成一块（推荐，不改渲染器），要么扩展渲染器；推荐前者：同一实例的子项在 CPU 上合成一块蒙版，编号为 `combined:<实例>`。
6. **增删**：新建实例写入它的默认参数；删除用 `commit_fragment_replacement` 去掉该实例前缀的全部记录。撤销、重做、历史都已经按整份文档快照工作，不用改。
7. **预设和同步**：预设按“能力”存整个 `color.local` 片段，复制粘贴/同步也是，所以会带着全部实例走，行为是整体覆盖（和现在一致）。不做“只复制某个蒙版”。
8. **计费**：`export_charge` 的判断是“有没有非默认值”，前缀去掉后同一套逻辑适用，不用改规则。
9. **面板**：“局部”面板变成：蒙版列表（新建、重命名、删除、选中）、选中蒙版的子项列表（添加/减去、删除）、该蒙版的滑杆。滑杆绑定的参数编号带当前实例前缀；`SliderBinding` 的 `parameter_id` 直接写 `m2:exposure`，`slider_spec` 去前缀取范围。固定的“全图”项对应现有的全图调色，不属于这个能力。
10. **画布手柄**：画布叠加层只显示当前蒙版当前子项；拖动手柄改这个子项的 `gradient_*` 参数（拖动中走预览，松开提交，与滑杆一致）。这一步依赖本方案先落地。

## 为什么不用别的格式
- **每实例一个能力片段**（`color.local#2`）：要动能力表、管线顺序、预设模块、计费分类，改动面大得多。
- **新记录类型存实例列表**：要给编辑文档加类型、编解码、旧版本兼容和损坏恢复，而且历史、预设、同步都得另外适配。
- 前缀方案只改参数编号的解析（`find_parameter_mode` 一处加前缀处理），其余机制原样复用。

## 风险
- 旧版本程序打开带前缀参数的文档：参数当作未知字段保留，但这些实例不画（和“能力片段版本过新”一样跳过绘制）。需要把 `color.local` 的 `schema_version` 升到 2，让旧版本明确跳过整个片段而不是画出缺实例的结果。
- 实例编号上限和子项上限要有，否则文档可以被无限撑大（建议实例 32、每实例子项 16）。
- 没有实测的官方行为：多蒙版的合成顺序、“全图”与蒙版的叠加方式、子项减去的像素结果。实现时按上面的顺序做，并在证据文档里标明未核对。

## 分步实现（每步单独提交、三套构建全绿）
1. 参数编号前缀 + 兼容 + `schema_version` 2 + 登记 `name`、`combine`；模块按实例编译；单元测试（旧文档不变、两个实例两个绘制步骤、前缀非法被拒、实例上限）。
2. 子项（`s<K>`）与组合（添加/减去）：`combined:` 蒙版在 `gpu` 里合成；测试并集与差集。
3. 壳层：蒙版列表、子项列表、滑杆带前缀；删除、重命名；冒烟。
4. 画布手柄：渐变的拖动创建和手柄编辑。
5. 预设、同步、计费的回归测试。

## 需要确认
1. 参数前缀方案是否可以（推荐），还是要换成另外两种之一。
2. 实例和子项上限：32 和 16 是否够。
3. `color.local` 升到 `schema_version` 2，意味着旧版本程序会跳过局部调色而不是部分画出。

## 实施记录

### 第 1 步（2026-11-08 完成）
- `color.local` 参数编号允许 `m<N>:` 前缀（`split_local_parameter`、`local_instance_prefix`、上限 `kMaxLocalInstances` = 32）；`find_parameter_mode` 对 `color.local` 先去前缀；前缀不合法（0、超过 32、前导零、非数字、空基础名）查不到。其他能力不受影响。
- `color.local` 全部参数模式的 `schema_version` 升到 2。版本相关的几处都改成取自参数模式：`phase_one_version_limits`、`EditDocument` 提交和替换里的“版本大于 1 视为太新”（`max_known_version`）；提交写入时旧片段升到当前版本；模块 `migrate` 对 `color.local` 版本 1 直接升级；`write_back` 取 `max(旧版本, 当前版本)`。
- 模块编译：实例 0 之后按编号 1..32，有任何参数的实例各编译一个绘制步骤；`compile_interactive` 认带前缀的参数；渲染描述改用稳定排序，保证同一能力的多个步骤保持先后。预览里只有带前缀的值时也会编译（`EditDocument::preview_parameter_ids`）。
- 与方案的差别：`name`（蒙版名称）和 `combine` 这一步没有做——登记表不支持文本参数，名称留到壳层步骤由壳层自己存（或扩展文本参数）；`combine` 随子项在第 2 步做。
- 测试：`test_render_description`（前缀拆分和非法前缀、校验、实例顺序、只有预览值的实例、没有实例 0、版本上限）、`test_sync`（旧版本 1 片段可读、提交升到 2、重读仍在、非法前缀提交被拒、粘贴带着全部蒙版）；`test_preset_library` 的“太新版本”用例从 2 改成 3。

### 第 2 步（2026-11-08 完成）
- 子项语法：实例前缀之后可再带 `s<K>:`（K 为 1..16），只允许子项自己的参数 `region`、`mode`、`gradient_*`；基础调整滑杆（曝光等）属于整个蒙版，带 `s` 前缀的被拒。`split_local_item`、`kMaxLocalItems`。没有 `s` 前缀的 `region`/`gradient_*` 是子项 0。新登记参数 `mode`（`add`/`subtract`，默认 add），不是绘制通道。
- 编译：一个蒙版里只有一个“添加”子项时蒙版编号照旧（`semantic:…` 或 `gradient:…`）；多个子项或含“减去”时合成 `combined:+<子项>|-<子项>|…`。区域为“整个画面”的子项不参与。子项值逐项校验，不合法的子项跳过。
- 像素：`gpu::add_gradient_masks` 也生成组合编号里的渐变子项；新增 `gpu::add_combined_masks`，在子项蒙版都在之后合成（添加取较大者，减去乘 `1 − 子项`），缺任何一个子项就不生成；renderd 和 exportd 在渐变之后各调一次。语义蒙版提供者和导出的“是否需要蒙版来源”都改成按展开后的叶子编号判断（`mask::leaf_mask_ids`）。
- 修了一个已有的隐患：登记表里 `region.default_choice` 写在后续 `add()` 之后，`modes` 重新分配会让引用失效；现在紧跟在选项后面设置。
- 测试：`test_geometry`（组合编号往返和非法编号、叶子展开、渐变子项生成、并集和减去的像素）、`test_render_description`（子项语法、校验、三个子项的组合编号、单个子项保持原编号）、`test_exportd`（线性渐变并集里挖掉一个圆：圆外 60→119 变亮，圆内 61→60 不变）。
- 并集取较大者、减去乘 `1 − 子项` 是我的选择，官方的合成像素没有核对。

### 第 3 步（2026-11-08 完成）
- 文档：`EditDocument::commit_parameter_prefix_removal`（删掉一个实例的全部参数，空前缀是实例 0；修订号加一，写盘失败不变）、`clear_preview_prefix`；`CommandGate::remove_local_mask`（走命令入口，登录态、极速导出、写锁、修订号都检查）；`PreviewSession::remove_local_mask`（进历史，步骤名 `local.remove`）和 `local_mask_instances`（从已提交片段和预览值里列出现有实例）。
- 壳层“局部”面板（`addLocalPanel`）：蒙版列表（新建、选中、删除）、选中蒙版的子项列表（添加子项：部位下拉加“添加/减去”，删除子项）、选中子项是渐变时的位置滑杆（线性没有椭圆比例）、整个蒙版的十四支调整滑杆。新建蒙版只是写它的 `region`；删除子项是把它的 `region` 写成“整个画面”（不参与）。结构变了（新建、删除、子项增减、撤销重做）才按文档重建，滑杆提交不重建。历史里的名字取“自定义-N 滑杆名 值”。
- 与方案的差别：蒙版名称没有重命名（显示“自定义-N”，N 是实例编号；需要文本参数，留到以后）；实例 0（没有前缀的旧数据）会作为“自定义-0”出现在列表里，可以删除。
- 测试：`test_sync`（删除实例只去掉它自己的参数、实例 0 单独删除、空删除和过期修订被拒、重读仍对）；壳层冒烟（新建蒙版、调曝光变亮、加线性渐变子项只亮一部分、再加径向“减去”子项变暗、删子项变回、删蒙版回到原样且多一步历史）。
- 还没做：画布上的渐变手柄（第 4 步）、预设/同步/计费的专门回归测试（第 5 步；计费沿用“有非默认值”的判断，冒烟里删掉蒙版后导出估算恢复免费）。

### 第 4 步（2026-11-08 完成）
- 画布（`PixCakeImageView`）新增 `CanvasHooks`（叠加绘制、是否接管鼠标、拖动三个阶段，位置是图像百分比）和 `imageRect()`；局部面板新增“在画布上拖动”开关（`refine-local-draw`）。打开并选中蒙版后：选中的子项是渐变就改它，否则新建一个（部位下拉选径向就是径向，否则线性，叠加方式取下拉）。
- 换算（`gradient_from_drag`，按图像像素算）：线性——中心取两点中点，角度取起点→终点的方向（屏幕坐标，向下是 90），范围取两点距离占对角线的百分比；径向——中心取起点，横向半径取水平距离、椭圆比例取纵横距离比，纵或横为 0 得到空蒙版时不写。拖动中走预览，松开提交。
- 画布上画出选中渐变的手柄：线性是连线加两端圆，径向是外椭圆、内椭圆（按羽化缩进）和中心点。
- 已知限制：松开时每个参数各提交一次，一次拖动在历史里是几步（线性 4 步、径向 4 步，另加新建子项的 1–2 步）；官方是一步。要合成一步需要一个“批量提交多个参数”的命令，留作后续。手柄只用来显示，拖手柄改位置/大小没有做——想改就在画布上重新拖一次（会改同一个子项）。
- 测试：壳层冒烟里用鼠标事件在画布上拖：线性从 (40%,30%) 到 (40%,70%)，参数是中心 (40,50)、角度 90、范围按对角线算；亮度比整个蒙版低；反方向再拖改同一个子项且角度翻转；径向从 (50%,50%) 到 (70%,60%)，中心、范围、椭圆比例都对。
