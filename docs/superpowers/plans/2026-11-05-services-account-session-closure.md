# Services Account 本机会话边界闭环计划

日期：2026-11-05

## 背景和审计结论

架构规定 `services/account` 负责把登录身份、商家关系、余额和工具包订阅同步进本机
缓存；需求规定本机已有会话时直接进入主页，退出登录只清会话，不删除本地项目库。C-51
还要求自定义工具栏最多 5 个、收藏色最多 6 个，且这些布局属于账号侧，不写入每张图的
精修文档。当前仓库没有 `services/account`。

本计划只实现账号快照校验、本机会话缓存和布局上限，不实现短信、微信、商家账号的网络
认证，不保存项目数据，不在壳层直接修改账本余额。

## 实现任务

### Task 1：冻结账号快照 `[x]`

- 新增登录方式、账号身份、商家编号、剩余张数、创意点数和工具包订阅类型。
- 张数与创意点数保持两个独立非负字段；订阅编号和身份编号拒绝空值、NUL 和重复项。
- 会话令牌作为不透明句柄保存，不解释认证内容，不写日志。

### Task 2：实现本机会话生命周期 `[x]`

- 无缓存返回未登录；有效缓存恢复已登录快照。
- 缓存校验失败返回状态冲突并保留当前有效快照，不把余额改成零。
- 登录替换快照；退出登录清掉账号会话但不调用项目库、不删除本地项目数据。

### Task 3：实现账号侧布局上限 `[x]`

- 工具栏能力引用最多 5 个，收藏色最多 6 个；超限请求拒绝且不改变已有布局。
- 工具栏和收藏色只保存在账号快照，服务不把它们写入精修文档。

### Task 4：测试、门禁和证据 `[x]`

- 覆盖两套余额独立、缓存恢复/失效、登录/退出、订阅保留、工具栏 5 个和收藏色 6 个边界。
- 新模块保持无 Qt、无 OpenGL、无项目库、无账本实现和无网络依赖。
- 更新计划与证据，执行全量 CTest 和 `git diff --check`。

## 验收条件

- 本机会话状态和账号快照可验证；退出只清账号状态，不触碰本地项目。
- 余额字段永不合并；坏缓存不会产生零余额；布局超限不会部分写入。
- 全量 CTest、架构依赖门禁和 `git diff --check` 通过。

## 明确不在本阶段

短信/微信/商家网络认证、账号服务 HTTP 协议、支付、余额扣费、项目库、远端同步和 UI
登录页面继续保持在后续计划。
