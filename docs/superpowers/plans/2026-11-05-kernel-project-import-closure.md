# Kernel 项目导入编排闭环计划

日期：2026-11-05

## 背景和审计结论

`2026-11-05-kernel-import-admission-closure.md` 已完成四类图片的头部准入和来源身份
采集，但还没有把合格来源交给项目索引。架构规定 `kernel/project` 是项目和图片
记录的主人，`storage` 只保存索引，批量中一项失败不能回滚已经成功的其他项。

本计划只实现内核侧的批次编排：先用 `kernel/import` 验证内容，再调用现有
`ProjectLibrary::add_photo` 写入单张项目索引，并返回逐文件结果。它不把 SQLite 放进
导入模块，不复制像素，不处理 UI 拖放、RAW 解码、EXIF/XMP、缩略图或网络来源。

## 实现任务

### Task 1：冻结批次输入和逐文件结果 `[x]`

- 新增导入候选、逐文件结果和批次结果类型，携带路径、文件名、访问凭证、结果码、来源格式/尺寸和照片编号。
- 空批次直接返回 `StateConflict`，不访问项目库、不写文件。
- 批次结果记录每个文件的原因；总体结果为成功或第一项失败，不能隐藏部分成功。

### Task 2：接入准入和项目索引 `[x]`

- 每个候选先经过 `probe_source`，只有准入成功才调用 `ProjectLibrary::add_photo`。
- 成功项写入项目索引并保留文件身份；失败项不写入，后续候选继续处理。
- 不在导入模块实现 SQL、不把像素或缩略图写入项目库。

### Task 3：边界和失败语义 `[x]`

- 项目不存在、项目在回收站、空路径/文件名、缺失、权限、损坏和不支持格式均返回明确结果码。
- 一个候选失败时，已成功候选的项目记录保持不变；重复调用只按项目库现有约束处理，不额外扣费。
- 访问凭证只传给项目库，不写日志、不进入导入结果文本。

### Task 4：测试、门禁和证据 `[x]`

- 覆盖空批次、全成功、部分成功、全部失败、项目状态冲突和身份持久化。
- 确认导入目标只产生项目照片记录，不产生像素文件或参数文档。
- 新目标保持无 Qt、无 OpenGL、无网络；更新计划和证据。

## 验收条件

- 有效候选被逐个加入项目，结果含照片编号、格式、尺寸和来源身份。
- 中间失败不影响其他候选，结果按文件列出失败原因，空批次不产生副作用。
- 全量 CTest、架构依赖门禁和 `git diff --check` 通过。
