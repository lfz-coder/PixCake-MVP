# 内核审核问题修复 Implementation Plan

> 目标：处理 2026-11-03 内核实现审核中已复现的安全、一致性和数据完整性问题。每个批次都必须先加入能复现审核反例的失败测试，再实现修复，最后同步原计划状态。未被需求、架构或官方页面明确描述的行为不得自行扩展。

## 约束与证据边界

- 所有持久化写入必须保留最后一次成功保存的数据；失败时不得删除用户文件、覆盖不属于任务的文件或伪造成功事实。
- 账本的去重和余额判断必须在持久存储事务内基于最新事件判断；单个 C++ 对象的锁或缓存不能作为跨句柄一致性保证。
- 导出任务必须持有可重启解析的不可变快照或版本引用，并在入队、重放、发布和清理时验证目标根与文件所有权。
- 历史选择只改变当前编辑内容，不改变单调递增的文档修订代数；原图与副本必须拥有独立编辑实例身份。
- 未知能力片段、过新版本片段和未被当前操作提供的片段必须原样保留；不可理解不等于可删除。
- 图层旧文件只能迁移或停用无法理解的字段，不能把整个可校验文件判为损坏。
- 用户可见展示继续以官方《工作区页面介绍》为最高依据：[https://www.pixcakeai.com/guide/32445](https://www.pixcakeai.com/guide/32445)。Jarvis 复核的测试应用是 `/Applications/pixcake-test.app` 9.3.0；知识库未连接，不补充未确认的滑杆、账号或 GPU 行为。
- 不引入 Qt、OpenGL、HTTP、推理运行时或第三方测试框架；不修改用户已有的未提交图层文档和规格修改。

## 修复批次

### 批次 A：账本跨句柄一致性与资格校验

范围：R01、R10、R21。首先修复跨连接重复扣点和加速绕过订阅；随后为同一导出批次增加持久批次身份，允许分次完成只结算一次。

验收：两个 `SqliteLedgerLog` 打开同一文件时，第二个旧快照不能追加重复 start/stroke；余额和事件只有一份有效扣费。大师精选非订阅任务在前三次免费次数耗尽后，即使先调用 accelerate 也必须拒绝启动。导出批次 A、B 分次完成时只扣一次，新的导出批次仍可扣费。

### 批次 B：导出路径、文件所有权与可恢复快照

范围：R02、R03、R08、R09、R14、R17。将用户选择目录保存为根约束，拒绝 `..`、目录软链接逃逸和跨根发布；任务快照可在重启后解析；发布采用不覆盖策略并校验临时文件身份；单任务目的地失败不能阻塞其他队列项；清理、刷盘和权限失败必须留下可重试状态和原因。

验收：所有越界和碰撞反例均不改用户已有文件；重启后仍可得到原修订正文；有效任务能越过失败任务继续处理；超时或回滚失败不报告成功。

### 批次 C：编辑修订、历史身份和未知片段保护

范围：R05、R06、R07、R12、R13、R15。统一文档提交串行区，历史分支写入新修订；副本获得独立编辑实例 ID；同步、预设、烘焙和批量替换保留未知及过新片段；重试按稳定目标 ID 关联结果；能力资格、数值范围、UTF-8 可见字符和网格边界使用同一元数据来源。

验收：任何公开编辑入口都不会把修订写回旧代数或绕过极速/占用门闩；失败不会留下半写文件；预设和同步不会删除未提供的片段；非法范围、非法 UTF-8、组合字符和网格边界按契约处理。

### 批次 D：图层旧文件、项目库迁移与源文件删除事务

范围：R04、R18、R19、R20、R22。增加旧 PXLD 字段迁移/停用策略；项目库 DDL 在可重试事务内完成；源文件删除使用入库文件身份而非重新解析路径；删除意图可恢复，隔离后的空文档状态持久可见。

验收：旧文件的可理解图层、蒙版和生成记录保留；迁移中断后下一次打开可继续；路径软链接换向不会删除错误文件；删除失败不会造成索引与磁盘分裂；隔离后重复打开仍返回恢复为空。

### 批次 E：性能、诊断和架构门禁

范围：R16、R17、R35、R60 及审核中列出的性能/构建问题。缓存采用受影响行增量更新；批量标记使用单事务批处理；记录阶段、原因、耗时和去重结果但不写像素或凭证；依赖检查覆盖所有 kernel 目标并在构建阶段失败。

验收：2000 项操作不出现全表删除重插或逐项往返；失败可区分权限、缺失、损坏和未完成；违规依赖无法通过构建。

## 完成定义

本计划只有在批次 A–E 的失败测试全部转绿、审核反例重新验证通过、全量构建与架构检查通过后才可标记完成。单独的 22/22 CTest 通过不能替代审核反例验证。
