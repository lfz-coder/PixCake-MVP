# Kernel 生成任务边界闭环计划

日期：2026-11-05

## 背景和审计结论

`2026-11-05-kernel-preview-pipeline-closure.md` 的 5 个任务已经逐项完成，验收为
35/35 CTest 通过。它只关闭了预览、绘制描述和内容协议，并没有声称整个 kernel
完成。架构合同仍明确要求生成任务描述、结果形态和取消状态由内核定义；当前仓库
只有 `layerdoc::place_result` 的落层形态，没有独立的生成任务边界。

本计划只落实上述生成边界。它不实现远端 AI、网络请求、点数扣费、结果像素解码、
生成进程、图层写入或配置服务；这些仍由各自的后续计划负责。所有规则都来自
`docs/superpowers/specs/2026-11-02-pixcake-kernel-architecture-design.md` 第 6.11
和第 8 节，不对未写明的价格、模型、文件格式或服务行为做推断。

## 实现任务

### Task 1：冻结生成工具和任务描述 `[x]`

- 新增无 Qt、无网络的 `kernel/generate` 公共类型。
- 固定工具编号、参数模式编号、结果形态、计费规则编号、生成张数和可取消标志。
- 对任务和工具标识做非空、无 NUL 校验；生成张数必须大于零。

### Task 2：固定六种结果形态和结果验收 `[x]`

- 只允许架构合同规定的六种结果形态。
- 结果必须绑定任务编号、结果编号、形态、序号、像素文件标识、校验和和正尺寸。
- 结果携带供图层文档继续编辑的透明参数载荷；内核只传递，不解释工具私有格式。
- 序号不得超出任务声明的生成张数；不在 kernel 中读取像素或调用解码器。

### Task 3：实现任务状态迁移 `[x]`

- 覆盖已报价、排队中、生成中、成功、失败、排队取消、生成中取消。
- 排队取消不进入扣费逻辑；生成中取消进入终态且不允许晚到结果再次成功。
- 生成进程崩溃从生成中进入失败；重复入队、重复开始、重复失败/成功保持幂等，
  其他非法迁移返回 `StateConflict`。

### Task 4：测试、门禁和证据 `[x]`

- 为六种形态、坏任务字段、坏结果绑定、序号越界、取消和崩溃迁移增加测试。
- 新目标不链接 Qt、OpenGL、网络或账本实现；账本仍是实际扣费和事件持久化的唯一主人。
- 更新本计划和证据，明确本阶段只完成内核合同，不把生成服务标成已实现。

## 验收条件

- 每个架构规定的结果形态都有稳定枚举值和名称，未知形态不能通过校验。
- 合法任务和结果可以在进程边界传递为纯数据；无效绑定、空标识、越界序号和零尺寸结果被拒绝。
- 状态迁移与架构合同一致：排队取消、生成中取消、崩溃和晚到结果都不会恢复成成功。
- 全量 CTest、架构依赖门禁和 `git diff --check` 通过。

## 实现证据

- `kernel/generate/include/pixcake/generate/generation_task.hpp` 冻结任务、结果和状态类型。
- `kernel/generate/src/generation_task.cpp` 实现字段校验、结果绑定和幂等状态迁移。
- `tests/kernel/generate/test_generation_task.cpp` 覆盖六种形态、坏字段、结果越界、取消、崩溃和晚到结果。
- 验证目录：`/private/tmp/pixcake-kernel-generation-20261105`。
- 最终结果：36/36 CTest 通过，架构依赖门禁和 `git diff --check` 通过。

## 明确不在本阶段

真实远端 AI、服务配置和价格表、生成进程、像素文件写入/解码、图层文档落层、
导入解码、账号网络、`kernel-cli` 和完整应用进程入口继续保持未完成状态，不能由
本阶段的纯数据合同替代。
