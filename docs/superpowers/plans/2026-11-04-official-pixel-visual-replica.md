## 1. 计划结论

上一阶段完成的是五页 Qt 壳层的结构布局、文字契约、空状态、导航和 AX 验收。它没有完成官方页面图级别的视觉复刻，因此不能把当前界面称为“和像素蛋糕一模一样”。

本计划专门补齐视觉复刻范围：以官方手册中的页面图、用户提供的官方截图和网站实际图片资源为最高依据，建立可复用的 PixCake 样式系统，并逐页把登录、主页、精修、图库、创意五页调整到官方页面图的视觉结构和视觉密度。

“一模一样”的验收对象是固定窗口尺寸下的官方页面图视觉结果：区域比例、背景、图片裁切、控件位置、文字层级、颜色、边框、圆角、分割线、图标和空状态都要有证据并可截图对比。真实登录、导入、图像处理、AI、导出和云业务仍然不在本计划范围内。

## 2. 当前差距

当前登录页是普通 Qt 表单骨架，与用户提供的官方登录页截图存在明确差异：

- 缺少黑色全屏工作区背景；
- 缺少左侧人物宣传图及其裁切方式；
- 缺少右侧登录面板的官方宽度、垂直位置和留白；
- 缺少“手机验证码登录”标题层级；
- 输入框、验证码按钮、登录按钮的颜色、边框、尺寸和间距不一致；
- 缺少用户协议/隐私政策勾选行；
- 缺少微信图标按钮、商家账号按钮和 `or` 分割线；
- 缺少右下角帮助图标；
- 当前帮助按钮、登录方式按钮和表单标签与官方图中呈现方式不同。

主页、精修、图库和创意页也只完成了区域骨架，尚未完成官方页面图的颜色、面板材质、图标、控件状态、图片/缩略图占位和视觉密度复刻。

## 4. 官方图片和资源交付门禁

### 4.1 执行者先做的事情

开始写代码前，先从 `https://www.pixcakeai.com/guide/32445` 读取五页对应图片和图片实际尺寸，记录：

- 图片原始 URL；
- 图片自然宽高；
- 页面图中窗口/内容区域的比例；
- 页面图是否包含浏览器边距、标注线或说明文字；
- 能否直接取得原始图片而不是缩放后的网页预览；
- 登录页人物图、图标、Logo、背景图是否有独立资源 URL；
- 主页、精修、图库、创意页是否依赖独立缩略图或素材图片。

优先从网页的实际 `img/src/srcset`、页面资源和官方图片 URL 读取，不通过猜测重画图片。下载的证据资源只放入本计划专用的临时证据目录或 `docs/superpowers/evidence/assets/`，不得把未经确认的业务数据当作产品素材提交。

### 4.2 需要用户提供图片的条件

如果出现以下任一情况，暂停对应页面的像素复刻，不得自行寻找相似图片替代：

- 官方页面图 URL 超时、过期、需要登录或无法取得原图；
- 页面只显示压缩预览，无法确认原始尺寸和裁切；
- 登录页人物图或图标无法从官方页面资源中取得；
- 官方图片被标注、裁切或遮挡，无法确定实际 UI 样式；
- 同一页面存在多个版本，无法确认当前版本对应哪一张图。

届时向用户提出一次集中需求：请用户按页面提供官方原图或清晰截图，命名为：


如果登录页还有独立人物图、Logo、微信图标或帮助图标，再提供：

```text

wechat-icon.svg/png
help-icon.svg/png
```

用户提供的每张图都要记录来源、尺寸、用途和授权范围。没有拿到原图时，只能完成可证明的部分，并把页面状态标为“视觉资源阻塞”，不得宣称像素级完成。

## 5. 复用优先的 PixCake 样式系统

### 5.1 样式层级

在 `apps/shell` 建立可复用的视觉层，不把 Qt 类型放进 `ui/shell`：

- `PixCakeTheme`：颜色、字体层级、间距、圆角、边框、阴影、控件高度和状态；
- `PixCakeIcon` 或统一图标加载器：只加载有官方证据的图标；
- `PixCakePanel`：黑色工作区、深色面板、边框和空状态容器；
- `PixCakeButton`：主要按钮、次要按钮、图标按钮、禁用按钮和导航按钮；
- `PixCakeField`：深色输入框、占位文字、验证码行和错误/禁用状态；
- `PixCakeToolbar`：顶部导航、左侧工具栏、底部缩略图区和侧边栏；
- `PixCakeEmptyState`：空项目、空照片、空图层、空 AI 工具和预览占位。

页面只组合这些共用组件和页面专属组件。任何页面需要的视觉差异必须通过明确的主题 token 或组件变体表达，不复制五套近似 QSS。

### 5.2 Token 提取规则

从官方图和资源中记录并集中定义：

- 工作区背景色、面板背景色、输入框背景色、边框色、主按钮色、禁用色、正文色、次要文字色；
- 标题、正文、说明、按钮、占位文字的字号、字重和行高；
- 页面外边距、列间距、面板内边距、控件间距、按钮高度、输入框高度；
- 面板圆角、输入框圆角、按钮圆角、分割线宽度、阴影和透明度；
- 官方图标的尺寸、线宽、对齐方式和禁用状态；
- 图片填充方式、裁切锚点、缩放策略和背景留白。

Token 必须带证据来源和测量方法。无法从官方证据确认的值只能使用临时 token，并在验收中标记 `pending`，不能包装成最终设计常量。

## 6. 页面实施顺序

### 阶段 0：证据和资产冻结

产物：

- `docs/superpowers/evidence/2026-11-04-official-visual-assets.md`；
- 五页原图/截图及尺寸记录；
- 登录页独立素材记录；
- 需要用户补充的资源清单；
- 五页固定对比窗口尺寸。

通过条件：每页有可复用的官方视觉基准；缺失素材已明确标记并向用户提出集中补充需求。

### 阶段 1：建立共享视觉系统

实现 `PixCakeTheme`、面板、按钮、输入框、图标、工具栏和空状态组件，先用登录页验证主题 token，再让其他页面复用。

通过条件：页面代码不重复硬编码同一颜色、间距、圆角和控件状态；主题修改能同时影响多个页面；`ui/shell` 仍无 Qt 依赖。

### 阶段 2：登录页像素级复刻

按用户提供截图和官方原图完成：

- 全窗口黑色背景和窗口内容边界；
- 左侧人物图片的比例、裁切和定位；
- 右侧登录面板的宽度、垂直居中和留白；
- 标题、输入框、验证码按钮、主按钮和协议行；
- 微信/商家账号入口、分割线和帮助图标；
- 所有禁用/只读状态，不实现真实登录。

通过条件：固定窗口尺寸截图与官方图逐项对比，主要区域位置和比例一致；AX 能读取账号、验证码、6 位限制、协议行、登录方式和帮助入口；没有网络或账号副作用。

### 阶段 3：主页视觉复刻

复用主题、面板和导航组件，对齐官方主页的背景、左导航、顶部功能区、导入项目区域、常用/快捷功能和项目空状态。项目卡片、云标识、缩略图和数量继续使用官方允许的空状态，不伪造业务数据。

通过条件：官方主页图和本地截图在固定窗口尺寸下区域比例、层级、面板密度和文字位置一致。

### 阶段 4：精修页视觉复刻

复用顶部导航、工具栏、画布占位、功能区和缩略图区组件，对齐官方图的深色工作区、工具按钮密度、画布比例、右侧面板和底部区域。工具仍为只读/禁用，不启用图像渲染。

通过条件：12 项工具、顶部入口、画布、右侧功能区和底部缩略区在截图和 AX 中均可对应；不生成照片或 GPU 内容。

### 阶段 5：图库页视觉复刻

复用状态面板、侧边栏、视图切换和空网格组件，对齐官方图的深色面板、缩略图标识位置、网格空状态、批量删除入口、AI 挑图/预设/元数据区域和底部工具。

通过条件：视觉区域、边框、状态标识占位和三种视图入口与官方图一致；不设置未经证据确认的默认网格列数、筛选和排序值。

### 阶段 6：创意页视觉复刻

复用工具栏、画布、侧边栏、AI 工具箱和图层面板组件，对齐官方图的手动工具区、中央画布、底部缩略区和右侧面板。AI 工具箱和图层面板继续保持明确空状态，不列出未被官方确认的工具和图层。

通过条件：区域比例、面板位置、工具密度和空状态与官方图一致；不实现生成、计费、图层编辑或导出。

## 7. 固定窗口和截图对比

统一使用官方图对应的内容比例，并记录本地窗口尺寸。每页至少保存：

- 官方基准图；
- 本地实现截图；
- 叠加或并排差异图；
- 差异说明表；
- 未确认项和下一步动作。

对比顺序：窗口边界 → 背景和大区域 → 图片裁切 → 面板位置 → 控件尺寸 → 文字层级 → 图标 → 空状态。不得先调小图标或字体，再忽略大区域比例错误。

## 8. Jarvis 验收

Jarvis 只做 AX 和可见结构验证，不替代官方图片视觉判断。每页记录：

- 窗口标题和页面标题；
- 关键区域可见文字；
- 关键输入框/按钮/协议行/帮助入口；
- 禁用状态和空状态；
- 页面切换是否可达；
- 是否产生任何文件、网络、登录或业务副作用。

如果本地应用无法被 Jarvis 启动或读取，计划状态只能是“视觉代码完成，Jarvis 验收阻塞”，不能写成完整完成。

## 9. 自动化和架构验收

```sh

  -DCMAKE_PREFIX_PATH=/opt/homebrew/opt/qtbase \
  -DCMAKE_BUILD_TYPE=Debug

ctest --test-dir build-desktop --output-on-failure

```

smoke test 必须覆盖：`login`、`home`、`library`、`refine`、`creative`；同时覆盖页面启动、主题初始化、空状态初始化和页面切换，不触发业务动作。

只有同时满足以下条件，才能把本计划标记为“完成”：

1. 五页都有可追溯的官方原图或用户提供截图；

3. 共用 PixCake 样式系统已经建立并被五页复用；
4. 登录页达到官方图级视觉结果；

6. 未确认业务数据没有被伪造；
7. Jarvis 能读取本地应用五页 AX；
8. CTest、架构门禁和 `git diff --check` 通过；
9. 视觉差异表和最终验收文档已提交；
10. F01–F13 和真实业务能力仍明确延期。
